# R3-5f 基础设施刷新与岗位修正分开计数

## 目标

`DF-0002` 的第三次沙箱验证通过，后来发现 SDK Release 与生成工作流配置缺失。现有“刷新候选交付”把平台模板修复算进岗位代码最多三轮修正，导致已通过的岗位候选无法换用可信模板并复测。

## 范围

- 岗位代码失败后由模型修正仍最多三轮；不改变失败自动修正的判断。
- `WAITING_REVIEW` 的管理员刷新只复用经精确 SHA 校验的岗位代码，最多允许额外两次基础设施模板刷新；每次刷新都产生新 SHA，并重跑沙箱。
- 元智能体交付检查允许标记为 `infrastructureOnly` 的第 4、5 次验证；未标记的模型修正仍拒绝第 4 次。
- 新计数字段仅表示基础设施刷新次数；已有三次沙箱记录不被改写，旧评审与测试结论不能迁移。
- 基础设施刷新期间若 Git 交付失败，可在同一轮重试；重试沿用原 `expectedSha`，不再消耗刷新配额。

## 界面对齐

任务页把沙箱记录显示为实际次数，刷新按钮只看基础设施刷新上限。更新 `ui-checklist.md`。

## 验收

- 第三轮岗位测试通过时，第一次额外模板刷新可进入队列。
- 每次新 SHA 必须重跑沙箱；第三次基础设施刷新被拒。
- 非 `WAITING_REVIEW`、沙箱未通过或 PR head 改变时，刷新仍被拒。
