# R4-9 小程序流式调用修复

## 目标

小程序 `enableChunked` 收到的每个分块必须来自真实智能体响应；不得把用户输入切行伪装成模型输出。渠道凭证、已登记 appid、身份和配额在调用前校验，挂起与错误事件保留原语义。

## 依赖

- R4-8 的渠道发布和统一调用入口。
- `docs/design/Keel-智能体底座设计-20261014.html` 第 27 章。

## 接口与界面

- 业务后端将微信 openid 映射到已登录用户，并经 auth-gateway 换取 `aud=keel-api` 的用户令牌；令牌 `azp` 等于渠道登记的客户端 ID。小程序不向 Keel 发送未经验证的 openid。
- 小程序 `wx.request({ enableChunked: true })` 发送发布凭证、客户端 ID 和原始输入；Keel 校验令牌签名、受众、用户类型、`azp`、凭证及每小时配额后转发真实智能体 SSE。SDK 分块解码 UTF-8 并派发 token、final、suspend、error。
- 控制台渠道发布 tab 显示真正可用的入口及身份方式。

## 验收

- 假智能体依次输出 token、suspend、error 时，小程序端收到相同事件。
- 未登记 appid、凭证无效、超出配额在调用智能体前拒绝。
- 输入为任意文本时，服务端不得将其当作响应返回。

## 接入约束

小程序 `token()` 必须返回业务后端完成登录和换票后的用户令牌。独立的 Keel openid 直连映射尚未提供；线上微信真机及业务身份接入需部署后验证。
