# 日成本、总成本与历史账单对账

## 用户确认的范围

- 运行总览智能体表将「成本」改为「日成本」，增加「总成本」。日成本为上海时区当天 00:00 至今，总成本为全部历史已结算账单。
- 智能体管理卡片及详情使用同一费用口径。费用只统计 SETTLED 且 costCny 非空的尝试；待计费条数另外展示。
- 总览上方模型成本跟随时间筛选，累计模型花费始终读取全部账单。
- 从完整网关账单重建各历史日汇总，允许晚结算修正已封账日期，累计数字不能依赖可能漏记的旧汇总。
- 测试通过后提交、推送，等待 CD 成功再验证线上；无法访问的步骤须如实记录。

## 契约与界面

先修改 contracts/console-api.openapi.yaml，再同步 Java AgentSummary 和生成的 TypeScript。新增可选 totalCostCny、pendingBillCount、totalPendingBillCount；costCny 保持原字段名并明确自然日含义。SDK 没有此控制台 DTO，不增加无关 Python 模型。

原型 docs/console/Keel-控制台前端-20261014.html 的总览表已有累计费用列；用户确认以「日成本 / 总成本」覆盖其跟随窗口的表头。总览 KPI 时间范围保持原有行为。更新 r1014/ui-checklist.md。

## 实现范围

contracts/console-api.openapi.yaml；keel-server 的 registry DTO/controller、insight 费用聚合/使用量/总览、metering 日汇总及对应测试；LiteLlmClient 历史分页完整性；console API 类型与合并、总览表、智能体卡片/详情及测试；本 spec 和界面对齐清单；scripts/verify-cost-ledger.py 及 deploy/ci/smoke.sh 部署后只读账单对账。

## 正确性要求

- 以完整网关账单为统一费用来源，不把 Redis 每日预算计数当账本。
- 从同一份账单计算所选窗口和累计，日成本跨午夜重置而总成本不重置。
- 每条尝试按 attemptId 唯一；降级的不同尝试分别计费，同 requestId 的调用数去重。
- 历史全量读取失败或达到分页上限必须报错，不能发布截断后的总成本；不估算遗失账单，不把缺失当零。
- 历史重建可重复执行，不累加重复费用；晚结算可修正历史日；全部无调用的今天为已知零。
- 不修改业务账单、预算、审计，不发起模型调用来测试成本。
