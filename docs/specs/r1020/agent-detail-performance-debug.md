# 智能体详情首屏与元智能体调试认证

## 目标与范围

详情首屏仅使用本地登记信息、版本、资源和已保存自检；不等待外部追踪。默认详情 API 保持兼容，控制台显式请求 includeRuntimeEvidence=false。运行证据通过独立只读 endpoint 异步补齐；保留未声明能力既有叉号/短注，仅需要证据的格子尾部转圈，失败/超时尾部“暂无法验证”，提供重试。切换/关闭抽屉取消旧请求并隔离过期结果。

要素证据读取近7天最多一页1000条语义观测，不再查询追踪列表并逐条读取8个详情，不读取用户输入输出及账单。按智能体、环境隔离并按trace聚合循环/工具证据；兼容Cloud扁平attributes和嵌套元数据。仅声明的能力可以被证明。读取超时上限6秒，沿用429冷却，不把异常或限流当作能力缺失。成功缓存5分钟、失败15秒；缓存键包括智能体、环境、登记版本和清单哈希。证据仅代表近期运行记录，不替代版本发布门禁。

研发记录改为切换页签后按智能体在服务端筛选、游标分页；基础信息和用量分别显示。已有看板不带过滤参数时保持完整返回。

调试普通调用及SSE流都为meta-agent携带KEEL_META_AGENT_TOKEN，careermate保持自己的凭证，其他智能体不接收这两种凭证。不关闭运行端BridgeAuth，不改元智能体业务代码、提示词、技能、评测题集或发布门槛。平台修复不生成新的元智能体业务版本。

## 契约

新增 GET /agents/{name}/elements，返回 elements、manifestHash、checkedAt、unavailable（本次暂时无法验证的要素名）。空证据不等于错误；不可用要素有明确名单。新增字段均为可选，不破坏keel/v1。

GET /devflow/jobs 增加可选targetAgent/cursor/limit，JobList增加可选nextCursor。targetAgent出现时默认10条、最多50条，summary仍遵循原看板含义。

## 原型与验证

对齐20261014原型及r1014/ui-checklist；保留左侧图标和名称，加载圈位于格子最右侧。验证成功、超时、限流、未声明、无证据、跨智能体/环境隔离、版本切换缓存、请求取消及过期结果不覆盖。认证验证meta-agent/careermate/其他agent，以及真实BridgeAuth与SSE；部署后guandezhi页面验证首屏耗时、局部状态、研发记录延迟加载和真实调试。

## 挂起终态

元智能体需求草稿可能返回合法suspend，调试页面应展示提示和追踪，并显示“等待人工处理”，不报“没有收到完整回复”，不伪造final或已持久化消息数量，不自动确认、恢复、交付或发布。中继记录该合法终态的追踪，但不将挂起凭证或未完成内容写入后续会话上下文。
