# 模型与成本页按标签加载

## 问题

`#/models` 进页只发一次 `GET /insight/costs`。服务端串行翻完全部账单后再查 Key、渠道、路由、告警规则和生产线费用。页面没有账单列表。路由标签不展示账单；渠道表的「当前用量」只要窗口汇总；Key 标签只在「最近被拒绝的请求」里用到状态为 `FAILED` 的行。

## 行为

- 账单查询新增按时间截断。`GET /admin/v1/spend` 从新到旧，窗口内遇到早于起点的记录就停止。`ts` 为空或无法解析的行仍算在窗口内，不能拿它截断。`spendAll()` 保持原样，链路按 `traceId` 对账和总览全量账本继续用它。
- `GET /insight/costs` 增加可选查询 `section`：`channels`、`keys`、`routes`、`all`，缺省 `all`。
  - `channels`：模型用量、Key、渠道。用量仍汇总近窗口账单，响应不带账单行。
  - `keys`：Key、渠道、逻辑路由，以及最多 50 条 `FAILED` 账单。
  - `routes`：路由策略、逻辑路由、Key、渠道。不读账单。
  - `all`：上述合集，账单仍是窗口内最新 50 条。不再查询告警规则，不再附带生产线费用。
- 同一段里互不依赖的薄网关读取并行。成功响应按环境、窗口、section 在进程内缓存 30 秒。改配额、渠道、路由或轮换 Key 后作废。失败不写入缓存。
- 页面进入时只请求当前标签，壳和页签先出来，转圈只罩当前标签。当前标签返回后再补另外两个。创建向导只请求 `section=routes`。

## 验证

窗口截断不读下一页；空 `ts` 不截断；`routes` 不打 spend；`channels` 响应没有 `bills`；`keys` 只含失败行；缓存命中不重复打网关，作废后会再打。前端合并时，后一次没带上的字段保留前一次的值。
