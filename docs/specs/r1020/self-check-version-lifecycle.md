# 自检认证与版本生命周期展示

## 范围

- 自检读取 manifest 和执行五条无业务探针时，为 meta-agent 携带现有服务认证。其他智能体不接收该密钥。HTTP 401/403、清单格式错误、名称/语言不一致分别报告；未执行探针时追踪检查明确说明原因。
- 正式版本仍以智能体、来源环境、版本号唯一，不改写旧版本和旧门禁。护栏保存改为更新 v0 候选；无变化不新建候选。
- 版本接口新增可选 state（DRAFT/ARCHIVED/VERSION）和 publishedEnvs。v0 与同来源环境中更晚的正式快照哈希相同才标记 ARCHIVED；其余为 DRAFT。不删除历史。
- 当前发布环境来自各环境最新 release/rollback 记录；只按已绑定的评测 ID+镜像匹配版本，无评测 ID 的历史记录必须来源环境和版本号吻合，避免跨环境重名误关联。发布记录不等价于 Kubernetes 部署状态，页面称“当前发布环境”。
- 页面分开显示候选草稿与正式版本，已归档草稿只显示数量；历史评测按行取数，禁止用当前评分填充旧版或草稿。环境列改为来源环境，说明复合唯一性；不虚构变更说明。
- 保留已有 VersionEvidence 的历史评测修复。测试覆盖认证作用域/拒绝、真实 SSE 探针、草稿归档/新草稿、回滚发布环境、跨环境同版本、护栏保存不改写已发布快照。

## 原型对齐

沿用 20261014 原型详情抽屉和版本表的样式；增加草稿区、发布环境列和必要说明，同步 ui-checklist。部署后以 guandezhi 页面点击自检和版本表回读验收。

## 实例协议补充

认证修复后仍须处理元智能体本身的协议探针：仅在 ctx.eval_run_id 为 self-check 且输入精确为 {"text":"probe"} 时，入口返回 self-check step 和 final。普通用户输入 probe 仍走业务；正常评测标记不触发。通过真实 SDK/ASGI、BridgeAuth 和追踪管线，不调用模型、工具、提示词或写业务状态。单独覆盖此条件及拒绝伪装的测试；新镜像完成现有 55 条完整回归、门禁后发布新快照。
