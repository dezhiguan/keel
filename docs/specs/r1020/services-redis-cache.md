# R1020 平台与能力服务 Redis 共享缓存

## 范围
本次替换 `/insight/services` 的进程内聚合缓存，保持原有四个标签页和数据口径；按标签页拆分接口不在本次范围。Redis 使用现有部署 Secret 的 redis-url，新增 KEEL_REDIS_URL 注入，独立命名空间不读写模型网关业务键。

## 行为
- 以环境 all/dev/test/staging/prod 分键，JSON 快照跨副本和服务器重启共享。30秒为新鲜期，物理保留5分钟；过期快照立即返回，异步刷新；超过5分钟不再展示旧健康状态。
- SET NX PX + 随机持有者令牌互斥刷新，90秒租约，20秒续租。Lua 校验持有者后原子发布并释放；过期或失去租约的旧工作者不能覆盖新结果，也不能删别人的锁。参考 https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/ （单实例缓存刷新锁，不用于审计/预算等业务一致性）。
- 冷启动仅持锁者聚合；其他副本最多等待20秒共享结果，不重复向外部依赖发起查询。默认 all 环境定时预热。Redis不可用时500ms连接/命令超时与短路退避，退回有界的本机快照和本机请求合并，不阻止平台其他功能启动。
- 接口新增可选 dataStatus（复用已有 InsightDataStatus）；真实采集成功才更新时间，失败保留旧更新时间。页面每30秒静默刷新，切环境/离开取消旧请求；显示更新中/延迟并提供重试，不把缓存的健康状态冒充刚探测结果。Redis只是缓存，不能据此推断全平台高可用。
- 不修改外部API、不改审计/调用/费用逻辑、不改元智能体镜像或实例数。

## 验证
真实Redis容器测试两实例冷请求仅加载一次、环境隔离、重启复用、过期异步返回、采集失败保留旧值、物理TTL设置、续租与过期旧写者隔离。无Redis模式/故障回退与HTTP接口现有测试继续通过。前端类型检查和相关测试；提交推送后检查CI结果。
