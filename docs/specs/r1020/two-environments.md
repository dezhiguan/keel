# 平台可用环境收敛：staging / prod

用户要求移除dev/test环境，保留测试staging和生产prod，提交推送并等待部署后页面验收。

## 范围和兼容

控制台顶栏、智能体创建、候选编辑、提示词试用/生效、模型Key创建统一仅允许staging/prod；候选和提示词预生产生效仅staging。默认开发登记/编辑环境改staging。详情不再把旧dev/test记录列为可编辑候选，历史正式版本/审计/追踪仍保留原来源，不篡改历史。

Keel v1线协议的历史环境枚举仍可解码，数据库历史记录、现有资源凭证、底层模型非生产路由兼容不删除，不把dev研发类别、devflow名字、测试命令或SDK协议夹具当环境批量替换。新增写入边界拒绝dev/test。历史查询/退役入口保留，支持后续有审计的资源清理；不在本次变更中批量吊销其他智能体运行凭证或重写其生产配置。环境收敛不是自动将旧dev授权扩为prod。

## 实现

先更新console-api契约的可写环境说明/约束（响应和审计历史枚举保持兼容），再更新服务校验和生成前端类型。统一全局选择仅all/staging/prod；各表单跟随。提示词环境标签映射staging与production，旧标签仅留历史版本元数据。现有真实staging/prod发布行为和镜像部署职责不变。

## 验收与部署

单元/集成验证新默认staging、旧环境写入拒绝、候选/提示词仅staging、历史可读取；控制台类型检查和相关行为测试。合并现有已部署受控读分支和main上的预算UI，防止发布回退丢失修复。按既有main CI/CD部署，确认server/console健康；真实认证浏览器核对顶栏、创建、提示词、版本页与现有聊天。保留部署SHA/运行ID及证据，不发布个人助理prod、不改变其知识授权或预算。

部署首次完整回归发现元智能体闭环的SDK评测测试需要Langfuse，但该CI作业只安装基础SDK。修复该作业安装正式声明的[eval]可选依赖，不跳过用例、不改变SDK运行逻辑或门禁。
