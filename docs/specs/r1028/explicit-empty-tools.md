# Python SDK：显式空工具列表必须禁止模型工具选择

个人助理正式100条 ev_bd8819dc421e4ad98852052a961deb34 的工具 JSON 注入用例在无工具分析阶段执行失败；generation 为30个输出token且没有正常文本交付。核查发现 SDK `LlmClient.chat(tools=[])` 没有给网关发送 `tool_choice=none`，历史工具消息仍可能影响供应商的工具选择。不能把此类执行错误改判通过，也不能把意外工具调用丢弃后伪造成成功回答。

SDK 在调用方显式提供空工具列表且未指定 tool_choice 时发送 `tool_choice=none`，同时不构造虚假工具定义。`tools=None`、非空工具和显式选择维持原语义；供应商仍返回意外调用时，Context 继续按现有规则拒绝。流式/非流式使用同一组请求选项，不伪造流式输出。

保持完整输入窗口、模型、思考设置、输出上限、重试、任务成本归因与预算逻辑不变；不添加缓存。验证真实HTTP请求形态、普通文本/可用工具分支和完整 SDK 回归，然后发布正式 sdk-v1.0.35 wheel。助理只依赖正式发布且校验SHA-256的wheel，不复制底座源码。SDK源提交独立分支，避免触发与该助理无关的业务服务部署；正式制品记录源提交及发布流水线。助理更新后需CI、部署成功及完整100条真实评测，不能以单测或受控夹具替代。
