# R4：技能、记忆、渠道发布主流程验收与修复

## 目标

对已上线的 1017 QA 智能体执行技能发布、授权、运行时加载与评测；持久记忆的写入、召回、删除和评测隔离；渠道发布、真实调用、来源校验、反馈和配额验收。只把实际观测到的链路记为通过。

## 范围

- `keel-server`：允许经过服务身份认证的智能体读取自己的已授权技能；禁止读取其他智能体的技能。记忆删除审计使用被删记录的实际层级。
- `sdk-python`：技能读取与工具、记忆读取采用相同的服务身份断言。
- `console`：记忆页按真实数据展示持久记忆层级，不把任务和经验层误称为用户记忆。
- 渠道发布只修复实测缺陷；不改变既有身份模式或访问策略。
- 渠道增加按 ID 下线入口；下线后保留记录和审计线索，但凭证立即不能再换取入口或调用。

## 验收

1. 没有 manifest 声明或没有授权时，`ctx.skills.load` 被拒；有声明与授权时通过带签名的服务身份读取锁定版本，且不自动获得工具权限。
2. `USER`、`TASK`、`EXPERIENCE` 记忆可按智能体与用户隔离，删除后不能召回；评测流量拒写；审计仅记录条数与实际层级，不记录正文。
3. 匿名渠道可从托管页完成真实 SSE 调用；未登记 Origin 拒绝；达到小时配额后拒绝；反馈记录可读回。需要换票的渠道按用户令牌验证。
   渠道下线后旧凭证返回 `CHANNEL_ORIGIN_DENIED`，页面清楚显示“已下线”。
4. 修复后运行相关单元及集成测试、控制台构建；线上部署和复测以生产返回和追踪为准。

## 约束

遵循 R4-6、R4-7、R4-8、R4-9 及控制台原型。跨语言结构若有变化先改 `contracts/`；本任务不改变现有接口结构。保留工作树中其他任务的未提交改动。
