# R1 人工确认的有界续修

## 目标与授权

2026-10-18 用户确认继续修复。DF-0017 已消耗默认五轮及一次人工五轮窗口，仍有一项真实回归失败。沿用任务详情的补充说明弹窗，允许管理员再次主动开启有限窗口；不重置计数、不自动扩容、不新建任务替代失败记录。

## 范围

- 沿用 `POST /devflow/jobs/{jobId}/retry` 的非空 feedback、管理员鉴权、事务锁及精确 SHA 快照。
- 人工窗口最多三次，每次最多五轮；所有来源的沙箱提交累计仍不超过二十次。第十九轮开启时只剩一轮。
- 当前窗口尚有额度时仅补充说明，不增加人工窗口次数。窗口耗尽且状态允许时，提交说明才增加计数。
- 失败候选须具备当前交付 SHA 的完整沙箱 FAIL 报告。运行中、已合并或已申请 H4 的任务不得开启窗口。
- 新窗口保留历史提交/报告，清除旧审核与门禁结果；新 SHA 重新测试并审批。
- Python 元智能体已有 `maxAttempts <= 20` 校验，无新增跨语言字段；OpenAPI 调整 `manualRepairWindows` 最大值为 3，控制台生成类型同步。

## 界面对齐

对照控制台 20261014 原型的 S3 开发修复轮次及任务详情。沿用现有“补充说明并开启新修复窗口”操作，弹窗明确已开启次数、累计用量、本次最多新增轮次和二十次累计上限，提交后显示实际窗口而非固定五轮。
