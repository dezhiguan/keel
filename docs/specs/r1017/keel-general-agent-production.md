# 从页面生产普通智能体

## 问题

控制台“由智能体生产”只能填写七个固定研发岗位 ID。服务端和 meta-agent
也按这七个 ID 校验、生成代码，因而无法通过正常页面操作新建独立的普通智能体项目。

## 范围

- 研发类创建任务允许任意合规且未占用的智能体 ID，支持 Python
  `tool-agent`、`graph-agent`、`supervisor` 和 `chat-rag` 模板。
- 既有七个研发岗位仍锁定其原型模板和工具权限。普通智能体可从共享工具目录选择工具。
- H1 后由 meta-agent 根据确认需求生成实际 `role.py`、提示词和行为测试；
  每个产物仍交付到独立项目仓库，后续开发可由人或 AI 继续进行。
- 不放宽工具授权、沙箱、评测、人工评审和发布关口。
- 知识库需要独立 H3 授权；这次不绕过授权直接接入。
- 协作模板要从页面选择已登记的子智能体，并写入 manifest 的 `spec.delegates`；
  生成代码必须经 `ctx.delegate` 委派，不得写虚构的子智能体名单。
- 候选 CI 在独立项目内下载 SDK wheel，不能调用已移除的底座脚本。
- 沙箱读取不可变 Git 快照时允许短暂网络故障重试，并在启动失败时记录真实错误。
- 候选代码必须使用 SDK 的真实 `ctx.tools.call`、`ctx.llm.chat` 签名；多工具需求至少调用两个已选工具。

## 验收

- 普通 ID 能走完页面创建和 H1，产生独立项目 PR。
- 固定研发岗位的工具及模板约束继续有效。
- 普通项目实际生成行为代码与正常/失败用例，且能够通过现有沙箱校验。
