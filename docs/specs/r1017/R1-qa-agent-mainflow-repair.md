# R1：智能体主流程修复与复测

## 目标

修复创建向导因服务端缺失相对路径 `evals/seed.jsonl` 而回滚资源的问题；为五个 1017 验收智能体提供真实 SDK 运行服务、知识检索、工具调用与委派；部署后验证注册、自检、调试、评测、版本、追踪及统计。

## 范围

- `keel-server` 的 Langfuse 数据集开通使用随服务打包的基准用例；现有可配置文件路径仍优先，缺少两者时在开通前明确报错。
- 向导不应把模板选择解释为已部署；没有显式运行地址时只生成目标地址，运行健康探针决定自检结果。
- 有知识库的向导配置仍指向该智能体自己的服务，不复用其他智能体的 `kb-bench` 端点。
- 五个验收智能体使用独立的 manifest 和同一份可配置运行代码，分别部署成五个服务；`spec.kind: agent` 与能力声明按 R1-8 校验。
- 每个服务至少提供可执行任务路径。知识型任务调用受限知识库，工具型任务调用已授权共享工具；协调型任务声明委派对象并执行委派。
- 增加对应评测用例，并在远端核验实际链路和统计。未观察到的数据不视作通过。

## 约束与验收

遵循 P1-6、P1-8、R1-3、R1-8；模型仅经 `ctx.llm`，共享工具经 `ctx.tools.call`，知识库仅按 manifest 授权范围查询。Langfuse 只调用当前 Cloud v4 允许的数据集 API。成功标准为五服务 ready、开通资源 ACTIVE、真实请求及评测完成，且能在 trace 与统计中查到对应数据。
