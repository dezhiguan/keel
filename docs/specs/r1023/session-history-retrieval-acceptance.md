# 第二步验收：较早会话内容检索和摘要引用回查

2026-10-23，已合并[PR #23](https://github.com/dezhiguan/keel/pull/23)，平台代码1a6235e39928；个人助理升级提交fd4c9fa。正式SDK版本1.0.10，GitHub Release wheel SHA256：2fcd8add8dda0c5ea16df05c207bfd64ee07cc928b2a256941b3f3b2be7e1382。没有复制SDK源码、修改业务提示词、模型渠道、Key或日预算。

## 实现与边界

- 当前会话未过期原文按中文二元词/英文词检索，覆盖最近128条之外和已经摘要的部分。平台从SHA256(owner:session)标识解析真实会话，约束agent、env、owner；显示名不作为授权依据。
- 原文片段提供消息id、Unicode码点offset、totalChars、完整原文SHA256和hasMore；按id与offset可分页回查，不覆盖存储。SDK将有界片段作为不可信参考，最多使用2400估算token，与提示词、工具及近期完整轮次共同受原10000 token限制。
- 摘要携带[m:消息id]，只保留来自已知原材料的引用。sourceIds从同一版本内容导出，随原子CAS一起更新。旧版本回查返回stale和最新摘要；SDK最多按新版本重查一次。
- 竞争失败后SDK采用数据库返回的权威版本/游标，重新选择尚未覆盖的完整轮次，不把被拒绝的候选当作已保存版本。独立SQLite模式提供同样的检索/引用能力。
- 检索和引用回查总时限6秒，失败继续正常聊天；评测、显式空历史和超限当前输入不读取旧历史。原文仍按既有7天保留，当前输入及工具链不被截断。

## 真实验证

使用隔离测试owner创建135条平台消息：一条包含随机交付编号及日期的用户事实、一条真实网关模型确认回复、一条25019码点长原文，以及132条明确标为占位的用户消息。占位消息仅用于构造窗口，未冒充模型回复或真实用户历史。向Pod只传最新128条，最早id278；关键事实在id271/272，长原文id273，均未随近期历史传入。

旧SDK1.0.9对照未成功召回：模型尝试业务知识检索，由于隔离测试身份没有登录后的业务工具授权，返回TOOL_NOT_GRANTED（trace f7a1da6d7c9387b24258b6f11fbb1f7c）。该对照不作为纯模型记忆能力评分。升级后相同问题可直接用会话历史回答，未调用业务工具。
