# R1023 上下文维护计量与聊天异常恢复

复现来源：个人助理 staging 的真实上下文验收。三条取消的摘要 generation 缺失 usage/requestId，账单已有结算；追踪只补金额，导致 token 分别少3389、3374、4014。同一聊天 requestId 重放重复推理。90秒无输出触及反代空闲超时。客户端断流时网关立即关闭厂商流，丢失尾部 usage，留下未知预占。

## 实现边界

- 在平台底座修复，沿用个人助理正式 SDK、业务镜像、提示词和10000 token硬上限，不改预算、Key、模型价格或业务门禁。
- 追踪详情及列表以同一 trace 的网关已知 usage 汇总 token；请求ID匹配的节点回补 usage。仅在一个缺ID节点和一个未归属请求时允许唯一关联，多义时不猜。调用已取消节点仍保留失败状态；已结束根 agent.run 的明确状态代表整轮结果。
- 控制台稳定 requestId 扩展到整个聊天入口：PG按owner/agent/env/session/requestId原子认领，绑定原始文本哈希。完成后重放原终态，不再调用模型或追加历史。执行中/结果未知拒绝重复执行；同ID不同文本拒绝。7天保留，普通评测不写用户幂等记录；挂起含恢复凭证不缓存。断流不能自动重算。
- 控制台异步执行210秒；进程退出未收尾的RUNNING在5分钟后转UNKNOWN，定时及重放入口均检查。过期不重新授予执行权；原执行者若稍后拿到真实终态，允许UNKNOWN回填COMPLETE，后续取消清理不得覆盖COMPLETE。
- 聊天反代每15秒接收SSE注释心跳，保留真实终态；SDK和应用的现有超时仍有效，不通过无限延长执行规避错误。
- 网关在客户端断流后停止下发，继续在原请求期限内读取厂商流并结算最终usage；有界保留尾部数据。期限到达关闭上游；确实拿不到usage时仍PENDING，不伪造零消耗或直接释放未知费用。
- 历史PENDING没有可验证usage，不人工清账。此次修复防止新的客户端断流丢失可获取usage；旧记录需供应商用量凭证另行对账，不能宣称已退款。

## 验证与交付

Java专项覆盖取消摘要账单回补、相同模型多请求/降级/多义关联、列表和详情一致、流断开后尾部usage及截止时间、真实PG跨实例请求去重/冲突/未知结果、SSE心跳及断流终态。执行服务完整测试和CI门禁，提交推送后等待目标服务双副本部署，复测原三条trace、正常压缩、重复请求、长输出和主动断流，记录真实账单和仍未知项。

接口沿用既有可选requestId、tokens、pendingBillCount字段。页面沿用调试及链路原型，更新对齐清单，不新增布局。
