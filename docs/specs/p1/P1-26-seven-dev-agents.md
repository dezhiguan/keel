# P1-26 元智能体生产七名研发数字员工

## 依据与验收目标

依据 `docs/design/Keel-全流程智能体化方案.html` 第 2～4、10 节和 `docs/console/Keel-全流程智能体化控制台.html`。本任务只生产研发层的七名员工：`dev-lead`、`spec-agent`、`dev-agent`、`eval-agent`、`code-review`、`ci-doctor`、`release-agent`。执行者是已有的 `meta-agent`；七名员工不能参与生产自己，也不能以人工预写的岗位实现冒充元智能体生成。

七名员工各有独立 manifest、私有仓库、运行身份、预算、人工种子评测集、门禁记录和注册/发布记录。各自能按第 2 节岗位职责处理非平凡输入，经真实调用及评测验证。仅有需求单、固定模板、占位入口、语法测试、Draft PR 或 `DELIVERED` 状态都不算“员工已创建/上岗”。

## 原型岗位与模板

| 员工 | 模板 | 最小可验证岗位行为 |
| --- | --- | --- |
| dev-lead | supervisor | 对业务员工需求分阶段委派给已授权研发员工，跟踪预算、失败与人工关口；自己不写代码/配置 |
| spec-agent | graph-agent | 需求表单 → 结构化需求单、岗位说明书草稿、授权清单；工具只能来自注册表，风险不降级 |
| dev-agent | graph-agent | 确认需求 → 生成实际业务代码、测试与 PR；在隔离沙箱运行测试，保留人写提交、冲突时挂起 |
| eval-agent | tool-agent | 人工种子用例 → 扩充边界/对抗/注入用例与评分草稿；不得修改人工原例或接触隐藏考题 |
| code-review | tool-agent | 读取 PR diff，审查模型调用、审计、工具审批、针对可见用例特判，给出可定位的评审结论 |
| ci-doctor | tool-agent | 读取 CI 日志和门禁报告，分维度诊断失败并给出修复清单 |
| release-agent | tool-agent | 部署 PR 到 staging，读取门禁与隐藏考题聚合分；通过后申请 `git.pr.merge` 审批，批准后才由 CI 发布并观察 |

工具和权限以原型第 2 节及真实工具目录为准；没有授予的工具必须拒绝调用。模型只能由 `ctx.llm` 调用，外部操作只能经过登记的 `ctx.tools`。元智能体自身没有修改自己的能力。

## 研发层生产状态机

研发层强制 `COLLAB`，执行者固定 `meta-agent`，管理员负责 H1～H4。按原型经过 S1 需求/H1 确认、S2 评测/H2 确认、H3 授权与 S3 开发、S4 代码及人工评审、S5 staging 门禁、H4 发布审批、S6 发布、S7 观察。状态、关口、产物和 trace 持久化，超时/失败/预算耗尽可恢复或人工接管；不能把 `COLLAB` 偷换成 `SCAFFOLD`。H1 确认后的骨架 Draft PR 是中间产物，不是成功终态。

模型生成岗位代码和提示词后，必须先在隔离沙箱验证。沙箱实际读取所提交的代码、执行契约测试、岗位行为测试及协议自检；不能以当前仅检查假服务应答的 sandbox runner 作为测试通过证据。CI/门禁必须绑定 PR head SHA；人工 review 和合并审批不能由元智能体代替。隐藏考题只由可信服务持有，智能体只读聚合结果。生产发布前必须校验上述证据。未运行的检查明确显示 `NOT_RUN`，不可标为通过。

## 七名员工的实测验收

为每个岗位准备人工输入与预期行为；元智能体分别执行独立生产任务。每个任务验收：需求单和 manifest 经 H1、种子评测经 H2、工具权限经 H3、模型生成的岗位代码由沙箱实际运行、真实私有 PR 由人 review、staging 门禁和 H4 发布审批有记录；注册/发布后 `/v1/invoke` 对岗位样例返回符合契约的结果，并能从任务详情跳到 trace、PR、评测、审批和发布记录。`release-agent` 的验收不能通过跳过审批自行合并。

GitHub 私有仓库分支保护和 Actions workflow 写入权限是硬前置。当前测试账号返回 `protection=UNAVAILABLE`、`checks=MANUAL` 时不得标记任务完成或员工上岗；应在界面和报告中显示阻塞项，等待有权限的仓库/凭据。不得用本地测试替代云端门禁结论。

## 实施顺序

1. 核实既有 D0/DF 能力和契约，补齐真实沙箱代码执行、模型代码生成及七岗可测试评测集。
2. 打通一个 `spec-agent` 任务的完整 S1～S7/H1～H4，消除错误状态和权限绕行。
3. 用相同生产线分别生产余下六名，逐项核对原型岗位行为、权限和质量门禁。
4. 在独立工作区完成测试、PR review、主分支发布和云端真实验收；保留每名员工的 job/trace/PR/commit/gate/release 证据。

## 本次已知缺口（开工核实）

- 当前 `meta-agent` 的 server workflow 只草拟需求、H1 和固定骨架 PR，未生成业务代码。
- 当前 sandbox runner 不克隆仓库、不运行测试；生成仓库的 CI workflow 因凭据权限只能交付为 `ci/keel.yml` 模板。
- 当前 GitHub 私有仓库分支保护受账号套餐限制，无法强制人工 approve；发布门禁不得降级。

这些缺口需逐项实现或解除外部权限限制；不能以缩小验收定义消除。
