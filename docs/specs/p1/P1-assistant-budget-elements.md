# 个人助理日预算口径与要素检查

## 问题与范围

个人智能助理控制台出现两处不一致：

1. 列表「日预算」取薄网关虚拟 Key（staging 为 ¥110），详情自检「薄网关 虚拟 Key 已发放」取清单 `dailyCny`（历史申请 ¥5）。
2. 要素检查将「模型自己调工具」「agent loop」标为缺失：清单是 `workflow` 且未写 `capabilities`，但已声明工具并在运行中产生多步 loop 与工具观测；现有逻辑对 `passed=false` 不拉运行证据、也不允许证据纠正。

本修复只改展示口径与要素证据读取，不改 Key 限额、不改发布门禁、不新建外部接口。

## 行为

- 详情摘要的日预算与列表相同：有薄网关 Key 预算时用 Key 合计，否则回退清单声明。自检「薄网关 虚拟 Key 已发放」的金额与摘要一致。
- 已声明工具但未写 `capabilities.toolCalling` / `loop` 时，两项为待验证（不直接打叉）；无工具时仍为缺失。
- 近 7 天 Langfuse 观测可证明上述两项（同记忆要素：真实记录可纠正，不靠空声明变绿）；证明后从 `missing` 去掉。
- 候选更新允许增补 `capabilities` 声明（非权限边界）；预算数值仍走既有 Key 配额授权，不经候选改写。

## 验证

- 后端：要素证据在有工具/无工具、有无 loop/tool 观测、预算 enrich 后自检文案；定向 `mvn -o -pl :keel-server` 相关测试。
- 助理仓：`agent.yaml` 日预算与能力声明与现状对齐，便于后续候选同步。
- 发布后核对 `keel-assistant` 详情自检金额与列表一致，要素 1、2 为通过或待验证后变为通过。
