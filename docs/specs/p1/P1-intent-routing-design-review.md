# 意图识别与任务路由设计复审修订（2026-10-25）

用户要求将本轮审核意见直接更新到现有设计方案。范围仅为本 spec 和 `docs/design/Keel-意图识别与任务路由方案-20261025.html`；不修改运行时代码、正式契约、控制台或其他工作区变更。

将方案修订为 v0.2 审核修订稿，保留现有 HTML 视觉风格，明确其为设计而非已实现或已发布证明。正文补齐：

1. 当前个人助理业务策略与平台通用机制的边界，以及本地源码核查的实现矩阵、证据路径和未完成前置条件。
2. L0/L1/L2 及每次动作执行前的独立授权校验；L0 同样产生最小结构化路由记录。
3. 意图动作、类型化参数与来源、可信运行时上下文、统一模式、步骤依赖、条件和部分执行策略。
4. 当前任务命令、写入回执、幂等、租约/fence、未知结果、取消、重试确认和授权复验的保留要求。
5. 慢识别的 SDK 结构化输出缺口、禁止向用户流式发送分类结果、失败处理与评测校准。
6. 远端能力目录、环境/版本隔离、持久化幂等、状态查询、取消、预算预留、真实费用及追踪关联的建设门槛。
7. 审计白名单与写入时机、分阶段实施与具有上下文/权限前提的正常及故障验收场景；行业官方资料与审核问题修订对照。

新增结构均标为候选设计，不作为当前 `keel/v1` 已存在字段；未来实现必须先更新 `contracts/`，现有 v1 上新增字段保持可选。对外组件接口不在本轮推定或改造。

验证：检查 HTML 结构、锚点与仓库内链接、模式和用例编号一致性；用浏览器检查桌面/窄屏可读性和脚本错误。文档修改不运行无关业务测试、不调用真实模型或部署服务。

验证结果：HTML 标签嵌套、ID 唯一性、10 个章节锚点、仓库内链接和 IR-01～35 唯一用例行检查通过。使用独立无头 Chromium 检查 1440px 桌面与 390px 窄屏，页面宽度无溢出，表格在自身容器内横向滚动，目录跳转及渐显正常，无页面脚本错误；已目视检查首页与场景表。业务代码与线上服务未改动。
