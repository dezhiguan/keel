# 第二步：会话内历史检索和摘要引用回查

## 范围

保留10000 token硬上限、原文7天保留期、最近128条传输窗口和现有业务提示词/Key/预算。只检索同一智能体、环境、用户作用域会话中的未过期原文，不扩展跨会话长期记忆。

## 实现

- 先扩展console-api契约：POST memories/session-history/search，GET memories/session-history/messages/{messageId}。请求使用平台已有SHA256(owner:id)会话标识；服务端从agent_session解析真实owner/id/env，禁止用显示名授权。服务身份必须匹配agent，普通用户必须是会话owner，预览身份拒绝。
- 全保留期内中文二元词/英文词检索，限定beforeId、结果条数和片段长度；命中提供原始消息id、role、offset、totalChars、SHA256，正文为明确标记的原文片段。按片段offset可回查其余原文，绝不改写存储。SQL参数化，原文及检索词不进入日志/审计。
- SDK在有历史的普通会话自动检索已摘要或128条窗口之外的原文，在上下文预算内注入不可信参考资料；固定当前输入超限不调用检索/摘要。检索失败不阻断聊天，显式空历史和评测不进行外部历史检索。
- 摘要生成保留[m:消息id]引用；只接受原材料及旧摘要中已知id。摘要GET返回从同一版本content导出的sourceIds，避免内容/引用分离写入。引用回查按会话范围核验，附带summaryVersion；版本变化返回stale及最新摘要，不把旧引用当作新版本证据。
- 修复SDK CAS冲突处理：采用数据库返回的权威版本与覆盖游标，重新选择未覆盖完整轮次；失败和冲突不能把未持久化候选误记为最新版本。并发请求使用单调游标和原有原子CAS，不用进程内锁替代跨副本控制。
- SQLite独立模式提供同样的本会话检索与引用读取能力。近期完整轮次和检索片段分别标明，合计仍受同一预算控制。

## 验收与交付

覆盖128条之外召回、长原文末尾片段、引用回查/分页、摘要版本变化和并发CAS、用户/会话/环境/agent隔离、过期隔离、检索故障和评测隔离、当前超限仍拒绝。真实验证区分隔离测试fixture与原用户会话，不将占位消息或固定回复作为真实模型证据。
