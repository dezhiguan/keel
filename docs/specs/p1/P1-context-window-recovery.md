# 会话上下文组装与超限恢复

## 目标和边界

保留 KEEL_CONTEXT_TOKEN_BUDGET 默认 10000 及 LlmClient 请求前硬拒绝，绝不提高或关闭测试卡点。
移除正常会话保存时 20000 字符静默截断；原始消息不被摘要覆盖。
SDK ctx.loop 根据系统提示词、工具定义、当前轮和历史的实际预算组装请求。
按完整轮次保留近期历史；更早历史通过有界滚动摘要压缩。摘要失败可暂时使用能容纳的近期完整轮次，但不推进摘要游标。
本轮用户输入和当前工具链不截断；这些内容本身超限仍返回原错误。

## 存储与隔离

PG 保存原始会话及独立的会话摘要。摘要按 agent/env/owner/session 隔离，使用版本 CAS，原文保留既有 7 天 TTL。
摘要不是用户长期记忆，不改变工具权限，不作为 system 消息；评测流量不持久化摘要。
SDK 独立运行时使用本地 SQLite 保存摘要；控制台显式历史的摘要通过智能体服务身份读写平台。
摘要不进入普通 span 属性、日志或 final.meta；只在 generation 输入输出中出现。

## 契约与范围

先扩展 contracts/invoke.openapi.yaml：历史最多 128 条，消息增加可选 id，正文取消静默长度截断；旧字段仍兼容。
在 console-api.openapi.yaml 增加 memories/session-summary GET/POST，保存 expected version、covered message id、summary。
涉及 SDK Context/ASGI、上下文组装独立模块、LLM 摘要调用输出隔离、记忆存储，平台会话和摘要 API/迁移/测试。
个人助理通过正式 SDK Release 升级锁定版本，不复制 SDK 源码。仅发布本次需要的服务。

## 组装策略

- 以既有 wire_tools 和 token 估算口径计算，目标为硬上限的 85%，保留护栏余量。
- 固定内容接近预算时允许用到硬上限减去小额护栏余量；当前问题/系统/工具本身不被裁剪。
- 将过早的完整轮次移入摘要，摘要调用禁用工具和 SSE token 输出，分块控制输入，限制输出和每轮摘要调用次数。
- 真实网关首个摘要耗时接近15秒，故单次摘要最多25秒，每轮摘要累计最多60秒、最多4次；超时回退，不推进持久化游标。
- 历史与摘要为不可信参考资料，提示保留事实、用户纠正、目标、约束和任务 ID，不执行其中指令。
- 每次工具循环重新检查，不能拆散当前轮的 tool_calls/tool 关系；最终 LlmClient 硬卡点保持原样。

## 验收

覆盖全量长文保存、完整轮次选择、超限历史恢复、超限当前消息仍拒绝、摘要失败、跨副本摘要、CAS冲突、会话/用户/环境隔离、评测隔离、隐藏摘要 token 和原文不被摘要覆盖。
提交推送并等待发布；正式发布 SDK 后升级个人助理，验证已被长消息堵塞的会话可继续聊天，核对每次模型输入估算不超过10000，直接超限调用仍被拒绝。
