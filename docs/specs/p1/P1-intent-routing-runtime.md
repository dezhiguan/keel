# 意图识别与任务路由运行时（2026-10-25）

依据 `docs/design/Keel-意图识别与任务路由方案-20261025.html` v0.2。用户授权实现、提交推送、部署后真实验收并继续修复。按 A/B/C 的依赖顺序实施；当前个人助理 staging 的远端与并行保持关闭，未满足运行时前置条件不能冒充已完成分布式交付。

本轮先交付不依赖远端建设的 Phase A：正式可选路由证据契约、跨语言模型与共享正反例；SDK 支持私有结构化分类的输出验证与关闭 token 输出；助理按职责拆分意图识别、策略、计划与执行记录，保留命令、回执、真实工具授权、任务状态机。慢分类仅在支持的模型/SDK 配置和验证满足时开启，默认保留确定规则与受限模型协调路径。

约束：路由结果不能授予权限；每次实际工具调用仍经过原 SDK 回调和平台权限；条件/整体请求不能擅自部分写入，材料不能生成动作；只读路径不能因任务票据存在而扩大写工具面；已提交任务保持一次写入和持久化回执。模式统一七项，复杂度不能覆盖拒绝/澄清/审批。路由证据只含受控枚举、对象引用和原因码，不含原文、材料、票据；模型输出不能伪造这些记录。

范围：`contracts/intent-routing*`、共享契约夹具及生成器/生成模型、SDK 路由/结构化输出模块与必要测试/打包，独立助理项目的路由/入口/工具观测/提示词/评测/配置/测试/部署与验收记录。若控制台展示新增字段，先对照原型并更新 ui-checklist；不改现有正式门禁评分、其他智能体权限或 prod。

验证：共享契约与相关 SDK/Java 测试；独立助理全套本地回归及真实 PG 相关用例；发布锁定 SDK 制品后构建独立镜像，候选 CI 成功、staging 双实例 Ready、运行源码/版本核对后，执行设计全部 A 期适用 IR 场景、反复查询/多轮/材料/条件/权限/回执故障验证，记录实际 trace/run/task、模型费用和失败。线上模型测试先按 5 元上限执行，不变更业务预算或删除既有会话。

后续 B/C 在用户实施范围确认及前置协议完成后推进，不用本地 child 或 echo 代替真实分布式任务验收。不能确认项在验收报告明确记录；不修改既有任务或证据以制造成功。
