# P1 会话事实冲突与记忆证据

## 范围

保留 10,000 token 硬上限、完整原文、原有摘要/检索及七天隔离。新增会话级事实账本；不把用户陈述当外部核实结果，不建立跨会话用户画像。

## 数据与一致性

先扩展 keel/v1 可选契约。平台 PostgreSQL 与独立 SQLite 保存 version/cursorId/facts/gaps；平台使用 agent/env/真实 owner/session 范围和原子 CAS。事实含实体、属性、时间/条件范围、原值、原文引用、active/pending/superseded/retracted 状态和替代关系。矛盾双方 pending；明确更正或针对性确认才能替代，时间/实体不同不能强行合并。否认保留撤销记录。助手回复、摘要内容不作为用户事实来源。

模型只建议有逐字原文证据的操作；确定性 reducer 验证来源、引用、目标、范围和状态转换。模型故障/非法输出不推进游标。当前消息暂用于本轮推理；持久化只覆盖已经保存的原文，下一轮重放，因此不把中断请求的候选写成事实。并发失败重读权威状态并重新分析，不覆盖胜者。已处理的原文按稳定 id 幂等。

每次有限批次读取待处理用户原文。输入过长不截断后冒充完整处理，记录 gaps 并在模型参考资料和链路标出 incomplete；原文继续可检索。账本容量和模型工作量有界，失败时继续近期历史聊天。评测、空外部历史、当前输入本身超限不写账本。

## 可观察性

增加 memory.summary、memory.history.search、memory.reference.read、memory.facts、memory.context 语义节点。只写版本、状态、消息 id、数量、摘要/原文哈希、offset、token 数，不在普通 span 写原文。generation 输入保留实际摘要/回查片段/事实参考。控制台节点详情展示白名单 memoryEvidence，并明确区分 attempted/used/failed，不把检索命中等同于模型实际采用。

## 验收与交付

覆盖明确更正、无明确替代的冲突、针对性确认、撤销、不同时间/实体、重复处理、伪造引用、助手幻觉隔离、CAS、跨副本、过期与越权、超长/失败降级。提交推送，通过 CI；正式发布 SDK、锁定助理依赖，部署后用真实模型验证，再通过 Langfuse v2 observations 与控制台 API 核对证据。保留原业务版本和正式评测门禁结论。

## 统一耗时预算
事实分析单轮最多35秒；加载、检索、事实分析与摘要共用每次请求60秒记忆工作截止时间，为业务回复保留时间。不得将新增事实分析35秒再叠加独立摘要60秒，从而超过助理90秒总调用期限。已耗尽预算时不调用模型或推进游标。

真实部署验收发现15秒不足以完成当前网关模型的结构化提取；失败后原受管理提示词仍会取最新说法。修复为35秒上限且仍在共享60秒期限内；无论提取失败、无事实、容量不足或未覆盖，都保留静态冲突规则，防止降级回“最新值获胜”。失败不推进事实游标。
