# 会话记忆维护异步化

执行依据：[设计与 M01–M14](../../design/记忆摘要与事实维护异步化优化方案-20261026.html)。本次实现第一阶段；合并摘要与事实模型调用是文档明确的第二阶段实验，保持关闭，不冒充已实现。

- 配对验收：PG agent_session 可选 maintenance mode 操作者覆盖，仅控制该会话的同步回滚；返回 maintenanceMode 协商 SDK 路径，并同时禁止该同步会话的异步投递与领取。正式 A/B 使用同一候选SDK/模型/提示词，只改变该会话策略，交替执行。
- SDK 选择 async/sync（默认 sync）。async 仅用于平台外部持久化会话：读取既有账本，明确未处理后缀与当前原文优先；按完整轮次裁剪，记录缺口并保留现有关键词原文回查。无平台队列许可时保持同步兼容。当前输入与工具链硬上限保持不变。
- 底座在 appendTurn 同事务登记 PG 持久任务，不在 SDK 创建易丢的请求后任务。摘要处理上界由可选 final.meta.memoryMaintenance 传递；facts 覆盖刚落盘用户原文。两个类型独立进度、租约、重试、有限 token/调用次数与成本预算。成功提交内容/游标和任务确认使用同一事务。
- SDK ASGI lifespan 后台轮询，以自身服务断言领取所属 agent/env 任务。每次领取新随机 fencing token、预期版本、目标消息范围；多副本 SKIP LOCKED。执行时加载原文完整前缀，每批不超过四个 chunk，成功只推进该前缀。超大单轮不能静默截断，任务明确失败/人工处理，不让正常多块积压永久卡死。
- 提交锁定原会话与任务记录，检查有效租约、版本、处理上界、完整来源和过期状态；删除同样锁定会话并删除任务/派生状态，防止任务复活。失败重试有上限，租约失效可恢复，重复投递合并目标；新目标不能使同一失败前缀无界重试。
- 后台单独 trace 关联触发 trace，memory.summary/facts 保持可视化；新增观测字段只含任务ID、区间、版本、数量和状态。控制台已有记忆节点可读，不新增产品页面；更新 UI 对齐清单。
- 正式发布新 SDK 后助理锁 wheel/hash；仅 staging 助理启用异步，保留同步回滚开关。发布前执行 PG/SDK 契约、故障恢复与真实 M01–M14 验收；长会话 A/B 各至少30、2/4QPS各5分钟、后台排空与成本对比必须保留原始证据，未达标不记通过。


部署压测跟进：ASGI调用固定HTTP/1.1，避免对付费POST发出不支持的h2c升级；流建立失败仅记录agent、HTTP状态或异常类型，不记录凭据/请求正文，也不自动重放可能已计费的请求。偶发连接失败必须重测并保留原始失败样本。

4QPS验收发现500m CPU配额下长上下文重复逐字估算拖慢事件循环。优化ASCII计数为C层编码计数，严格保持原估算数值和10000硬上限；不增加资源/模型配额，重新执行配对和负载验收。

最终CPU采样定位：RS256每次load_pem_private_key的RSA校验占据主要活动采样。采用进程内maxsize=2的已校验密钥对象缓存，不缓存JWT或claims；每请求新jti/签名，轮换PEM使用新对象，不跳过密钥校验，不持久化密钥。验收覆盖签名验证、跨client/audience、轮换与无效PEM。

4QPS长时间滚动额外发现：展示用source_ids默认截断16项被误用于摘要合法来源校验，导致第17项及以后的既有引用被拒绝，反向也可能漏验输出第17项虚构引用。校验扫描受摘要硬长度约束的全部引用；展示与回查上限保持16。增加合法第20项和非法第17项回归。失败目标仅在修复部署后受控重排队，保留旧attempt及费用，不由新请求自动重置。

补全服务端提交时来源校验：即便throughId仍有效，也逐一校验摘要中全部引用属于本owner/agent/session、位于已处理前缀且未过期；覆盖“旧引用过期但新target仍存活”与第17个越界来源。展示仍16项，既有非控制台通用v1摘要保持兼容。
