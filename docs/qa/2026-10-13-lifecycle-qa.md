## 已修复并部署

1. **Langfuse 网络超时**：旧手动转发进程占据 443，systemd 持续重启；恢复唯一 systemd 实例，并增加按 IP 的连接超时与故障切换。复查 `ActiveState=active`、`NRestarts=0`。
2. **智能体预算与凭据串用**：echo 模板曾忽略传入 endpoint，共用内置 echo 进程；修复 endpoint 解析、为自定义名称默认独立服务地址，并拒绝已撤销资源和错误共享 endpoint 的调试。
3. **调试环境固定 dev**：改为注册环境，并在调用与审计中使用同一环境。
4. **自检追踪硬编码失败**：改为核对实际服务身份、调用真实探针，并查询探针返回的 trace；探针带评测标记。
5. **跨数据集 seed ID 冲突**：Java / Python 均按数据集名称和原 ID 生成稳定 ID，避免将其他数据集的 409 当作导入完成。
6. **下线删除评测历史**：正常下线只撤销数据集资源绑定，不删除 Langfuse 数据集；其他访问凭据仍撤销。
7. **下线后重登记状态未恢复**：重登记后恢复 REGISTERED。
8. **调用量缺失**：从 agent / env 推导 trace 归属，成功调试保存 trace 索引用于累计统计；不在该索引中保存问题原文；排除评测探针。

- **P1：真实评测执行与任务持久化**。需要真正读取数据集、调用指定环境的智能体、执行配置的评分器、写入实验结果，并让所有服务副本查询同一任务状态。当前不能通过评测门禁，也不能验收完整晋级生命周期。

- **P2：自检结果持久化与重新检查入口**。资源发放后实例需加载新凭据，首次探针可能失败；详情页不能长期显示“未探测”而隐藏真实结果。
