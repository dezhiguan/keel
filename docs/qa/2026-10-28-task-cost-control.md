# 单任务成本控制与个人助理试点验收

日期：2026-10-27 至 2026-10-28（Asia/Shanghai）。依据：[底座设计](../design/Keel-智能体单任务成本控制能力方案-20261027.html)、[助理设计](../design/个人智能助理成本优化试点方案-20261027.html)、[实施 spec](../specs/r1027/task-cost-control.md)。

**结论：公共成本核心机制已实现，并在个人助理 staging 实际运行；两份设计的整体验收未通过。** 配对前台样本费用下降 20.3%，四轮记忆任务费用下降 26.4%，均未达到完整试点 30% 目标。最终 100 项正式评测为 54 PASS、43 FAIL、2 REVIEW_REQUIRED、1 BLOCKED；不得据此正式发布或扩大业务优化灰度。本次没有新增缓存，没有调整临时 10,000 token 输入上限，没有切换模型制造收益。

## 实现及运行范围

平台、网关、官方 Python SDK 和生成模板共同提供可信根任务、策略快照、费用归因、并发准入、后台传播与共享维护分摊。智能体无需复制账本或预算执行代码；个人助理的输入去重、特定检索证据组织及维护批次由 agent 策略显式启用，不推广为所有业务默认参数。

- 根任务 / 请求预留由 PostgreSQL 行锁控制，费用按网关 `llm_spend` 实际 attempt 结算关联。前台、分类、后台分析、记忆维护、失败、降级和未知付费分别保留；结算、执行、后台交付状态独立。
- 报价按实际输入、允许输出和路由尝试估算；执行前对实际选中路由再次原子复核。思考输出、候选输出和供应商限额误差进入预留；未知思考采用保守上界，不更改模型参数。预留不是已付费用。
- platform / org / env / agent 继承约束；根任务固定快照。管理发布执行 CAS、审计和继承冲突检查；当前更紧约束实时执行。回退追加新修订，不删除旧快照、费用或未知预留。
- HTTP 流式 / 非流式、直接 `Context.loop` / `Context.llm`、后台分析、维护 worker 均接入。认证入口区分 user / eval / load / memory / service；用户不能通过正文或接口自报 owner、额度或签发票据。可读响应不含票据。
- SDK 已正式发布 1.0.34；助理 0.5.12 仅依赖该 wheel 并校验 SHA-256，未复制底座源码。Python 模板启用自动接入，运行时能力校验拒绝未覆盖路径启用 enforce。
- 助理只去重完全一致规则 / 证据；针对 SSE 失败问题选取相关完整证据段并保留来源、版本与引用。需要全文、比较、冲突的请求回退完整证据。已有异步维护和选择性合并不是本次新增收益。

平台代码 `1f062b3`、助理代码 `5acab283` 已推送；最终 CI / CD / 冒烟全部成功，平台 server、llm 及助理均 2/2 Ready。最终部署版本、流水线与副本状态见 [运行证据](evidence/2026-10-28-task-cost-control/verification.json)。助理双副本逐一比对 74 个业务文件与 174 个官方 SDK 文件均无差异，见 [运行文件核对](evidence/2026-10-28-task-cost-control/assistant-runtime.json)。本次部署是 staging 候选，未创建通过正式门禁的业务版本，未推广 prod 或其他智能体。

对账窗口为 2026-10-27 14:10:00 至 16:21:27 UTC（北京时间 22:10 至次日 00:21），范围仅 `keel-assistant-staging` 网关请求：339 个请求 / 尝试，已结算 0.754784 元 = 直接归属 0.743986 + 已分摊 0.010798 + 未归属 0。共享原始费用也是 0.010798 元，重复分摊差额与总账差额均为 0，待计费 0。该窗口包含正式评测等调用，不等于全天账单，也不包含窗口前支出。见 [逐用途对账](evidence/2026-10-28-task-cost-control/model-fee-reconciliation.json)。

## 与两份设计逐项核对

“实现并验证”仅覆盖所列范围；PARTIAL / NOT_RUN 不是通过。

| 设计验收项 | 状态 | 证据与实际边界 |
|---|---|---|
| 权威费用、请求 / 尝试去重、共享费用守恒 | 实现并验证 | PG 集成测试、线上账单与任务关联对账；共享来源金额与分摊总和一致，未归属与未知单列 |
| 多副本预算、调用次数、路由变更、未知预留 | 实现并验证（数据库 / SDK 故障夹具 + 正常线上调用） | 真实 PG 并发测试；实际路由确认；第一尝试结算不能提前释放剩余尝试额度；未在生产强行制造付费中断或杀进程 |
| 策略层级、CAS、不可放宽上级、快照和回退 | 实现并验证 | 服务测试及线上管理 API 冲突 / 历史配置回退 / 新修订恢复；旧任务仍保留修订 7 / 8 |
| 前台 / 后台 / 维护 / 直接 SDK 自动关联 | 实现并验证（受支持 Python 路径） | 用户与 SERVICE 身份隔离；分析根任务不被子 trace 改写；维护按实际新增用户消息范围分摊 |
| 控制台成本管理 | 仅后端 / SDK | 任务、账单与策略 API 可用；本次没有新增任务成本面板或策略编辑页面，现有费用列保持原口径 |
| 新项目自动接入 | PARTIAL | 官方 SDK、模板与覆盖校验已更新，候选标准 runtime / 直接 Context 真模型已验证；尚未完整执行“新建独立项目—登记—后台—回退”的全部线上链路 |

| 按业务能力启用与完整材料 | PARTIAL | 无记忆评测无普通会话维护；普通检索与长分析实测；全文 / 比较 / 围栏完整性有单测，其他类型尚未全部代表性复验 |
| 动态预算与超过预算的业务处理 | PARTIAL | 实现材料规模预算、逐调用真实价格预留、清晰不可重试预算错误；没有自动授权加额、按任务类型细化配置、独立维护子额度或完整分段选择交互 |

| 首字 / 完整交付 P95 | PARTIAL | 小样本完整响应未恶化；首字 P95 未测，大规模错误率未测 |

| 隔离、删除、租约 / CAS 与恢复 | PARTIAL | PG / SDK / 服务测试及真实非法作用域拒绝；仅一个真实 USER，第二用户隔离场景 BLOCKED；删除排队竞争未做线上破坏性故障实验 |

## 正式质量评测与失败记录

最终运行 `ev_59b041f86b574905b301df2533fc246d`：100 项，99 项执行，54 PASS、43 FAIL、2 REVIEW_REQUIRED、1 BLOCKED，passed=false / complete=false。answer 13、classify 3、evaluate 4，数据集哈希及全部 100 项状态保留在 [最终正式评测](evidence/2026-10-28-task-cost-control/formal-eval-2.json)。

失败包括员工 / 会话路由澄清后未执行真实查询、受管理提示词证据不足、4 个受控夹具未被实际消费，以及自然上下文执行问题。2 项人工待审分别涉及 SSE 错误与 final 的完整区分、文档自称管理员不等于操作授权的明确表述。唯一 BLOCKED 缺少第二个真实认证用户；没有伪造身份。当前意图识别相关文件与成本改造前一致，且配对自然召回两组同样失败；**没有完整跑关闭优化的 100 项基线，不能把所有失败都断言为历史问题或宣称整体无回归。**

首次正式运行 SDK 1.0.33 为 11 PASS / 40 FAIL / 49 BLOCKED，暴露直接 Context 缺少任务关联，已在 SDK 1.0.34 修复并完整重跑；[首次失败记录](evidence/2026-10-28-task-cost-control/formal-eval-1.json) 保留。首次真实预算拒绝被分类器吞作澄清，已修复；后续验证返回 COST_BUDGET_EXCEEDED / retryable=false 且零付费尝试。早期测试 harness 令牌过期的 401 另行保留，不纳入已执行模型样本、不自动补造成本。

代码回归：官方 Python SDK CI 412 项通过；助理 CI 367 项通过、18 项 PG 依赖跳过；SSE Node 测试 3 项通过。网关最后一轮 90 项测试中 89 项通过（含 41 项 Gateway 测试及 9 项真实 PG 任务预算测试），1 项既有 Redis 测试跳过，不能写成全部覆盖。真实隔离 PG smoke 覆盖 atomic/shared/unknown/privacy/cross-owner/request-completion/migrations。最终付费输出边界修正另有针对性报价测试。

## 当前策略、回退及后续出口

仅 `keel-assistant:staging` 显式采用 enforce；maxCostCny=0.3、maxCalls=24、baseCostCny=0.06、perKInputCny=0.008、memoryBatchTurns=4、memoryMaxWaitSeconds=30，两项去重开启。0.3 是本试点费用天花板，实际根任务预算仍按材料规模计算；不是所有任务都会花 0.3 元，也不是全平台统一配置。最终修订及回退演练见运行证据。

管理 API 可从历史读取完整 config，以当前 revision CAS 发布旧 config；业务参数和执行模式分别可回退。不得删除账单 / 根任务 / 失败证据或释放未知预留。此次仅清理自动验收创建的普通会话，保留费用与正式评测记录，未触碰用户既有会话及未跟踪的用户 trace 文件。

下一出口应先修复并复验正式质量失败，补第二真实用户、TTFT / 负载收敛、独立新项目及跨类型接入验收；再在同容量、同模型和同材料条件扩充配对样本及校准任务类型预算。达到质量和费用门槛后才能扩大业务策略灰度。此报告记录尚未完成与未执行项，不作为完整发布通过证明。
