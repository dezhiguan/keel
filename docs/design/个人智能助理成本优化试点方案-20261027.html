02

接入通用任务账，补齐助理的业务归因

继承底座的完整任务费用口径。个人助理将普通交互、知识检索、跨会话回查和后台文字分析分别分组；后台分析通过根任务关联触发请求和实际执行，工具步骤与维护子任务不重复计作独立交付。

完整任务成本 ＝ 意图分类 ＋ 回答 / 分析 ＋ 工具后的模型处理 ＋ 后台记忆维护 ＋ 重试与降级尝试 ＋ 其他可归属的直接服务费用主要观测对象是网关模型账单；若存在单独收费的检索等服务，另列费用与来源，不隐去、不与模型费用重复累计。
  • 通过正式 SDK 传递可信根任务关联，底座与网关负责实际结算去重。助理补充任务类型、材料范围和业务完成状态，不自行维护第二份权威费用账。
  • 试点对一批维护新覆盖的用户轮次采用等额分摊，由底座保存范围与规则版本。共享摘要 / facts 调用只计一次；该分摊规则不作为所有智能体的强制默认。
  • 未结算或无法归属的费用单列。任务主回答完成、后台维护待结算时，费用状态仍为“待完整结算”；不能把它记成零成本。
  • 日常使用、评测、压测分组统计。失败任务费用保留；同时报告总支出、成功率，以及“全部同组支出 ÷ 成功完整任务数”，防止只统计成功样本造成费用虚低。

任务归因应形成可复核的守恒关系：已分摊费用＋独立后台费用＋未归属费用＝同范围账单金额。对历史恢复金额保留日精度，不强行分配到具体任务。

03

六项控制措施，优先消除重复工作

3.1 上下文按任务需要组织

模型能力、必要材料和任务复杂度决定上下文容量。固定提示词、当前指令、最新更正、相关原文及完整工具协议组优先保留；仅清理重复片段、无关字段、重复规则与已被替代的信息。新旧事实的替代关系和来源仍可回查。

  • 避免旧摘要、事实账本、历史原文和工具结果重复注入同一内容；不同来源提供的独有证据不能因主题相同就删除。
  • 当前材料本身是分析对象时，先明确需要的完整范围。分段处理必须覆盖全部范围，并保留跨段依赖，不用关键词截取代替完整分析。
  • 不为每次短问答额外付费生成压缩摘要。真正超过模型能力或任务预算时，采用可追溯的分段、回查或澄清，并统计其全部费用。

3.2 记忆按变化维护，合并连续待处理范围

沿用已实现的异步维护和选择性摘要 / facts 合并；进一步减少同一历史范围被反复处理。异步改善等待时间，只有减少实际 token、调用或重试才算降本。

  • 摘要按新增内容量、现有摘要覆盖范围和任务实际需要触发，不为每轮对话机械重写。
  • 普通维护可试验累计 4–6 轮或约 1,500–2,500 个新增 token 后处理，配合最长等待时间。这些数值只是维护批次的待调参数，不是主回答输入限制；必须通过质量和费用对照后确定。
  • 对独立致谢等明确无新增事实的输入，可跳过事实抽取；不确定时保持正常处理，不额外为每轮新增一次“是否值得维护”的模型判断。
  • 同会话积压按连续未处理区间合并，领取前重读游标，减少重叠付费。CAS 防止重复提交，租约与领取互斥负责减少重复执行。
  • 更正、撤回立即作用于当前回答，后台尚未完成不能让旧账本覆盖新原话。后台最长收敛时间可先以 60 秒为验收候选，按负载验证。
  • 维持摘要 / facts 各自校验、版本与进度；仅重试失败侧。当前 512 token 预计输入收益门槛是已有实现细节，不是未来上下文容量目标。

3.3 检索以证据充分性决定范围

当前知识检索一次取 8 条、单条最多保留 5,000 字符，可作为检查输入膨胀的入口。改为按问题范围选择必要片段与字段、去重并按需补查；不统一强制为固定条数或固定 token 数。

  • 返回实际问题需要的正文、来源、版本与必要元数据；删除无关包装字段。
  • 相同文档和片段去重；证据不足时有界补查，不能把被裁掉的材料当作不存在。
  • 保留截断和未覆盖标记。清单、审计或完整材料分析任务必须满足覆盖要求，不用少取数据制造费用下降。

3.4 调用按职责执行，减少无用分类与自评

现有普通聊天已采用单次回答路径，规则识别成功时不调用慢分类。继续保留这些能力，增量工作是覆盖高频明确表达和消除重复环节。模糊请求不能为了省分类费而被强行执行。

普通问答不默认增加模型自评；复杂分析按交付要求执行必要步骤，质量评审优先放在离线对照。评测中付费调用全部计入评测费用。

3.5 全链路统一重试与追加调用额度

由任务级预算协调应用、SDK、网关的重试与降级，避免各层叠加放大。错误按可恢复性处理；仅重跑失败部分，不把已经成功的材料分析或维护重新执行。

付费请求状态不明、客户端断流时先核对已发生的执行和结算，不能无条件重放。CAS 冲突后重读当前状态；失败预算不因新用户轮次被重置。保留失败、待结算和不确定尝试。

3.6 输出按交付内容控制

依据用户要求、任务类型、材料规模和输出结构估算长度，减少重复转述、套话及无必要的中间输出。详细方案、长材料分析和明确要求完整输出的任务按需放宽，不统一套用短回答上限。

本轮不新增精确答案、语义、多级、工具结果或向量缓存，也不把提高厂商前缀缓存命中作为降本措施。现有能力保持实际配置；后续若引入缓存，另立方案评估。

04

助理提供任务需要，底座执行动态预算

接入底座预算生命周期，不在助理进程中另建可绕过的预算执行器。撤回此前的固定输入额度及统一费用控制线；先建立真实任务分布，再按材料规模、必要步骤、历史使用需求和交付要求给出任务级预估依据。

控制时点动作结果要求
任务开始助理识别任务类型、材料范围与交付要求，不为估算默认新增模型调用；底座按策略与实际路由价格完成预算预估。形成任务级费用预估、允许的追加步骤及独立维护额度。
每次模型调用前SDK 传递用途与任务关联；底座 / 网关统一校验已结算、未决预留与本次调用额度。预算是费用约束；模型上下文容量是能力约束，两者分别判断。
接近预算优先停止可选自评和重复补查；普通维护可有界延后，但费用继续归属原任务且遵守收敛要求。不删除关键输入、不降低完整性、不以延迟结算制造降本。
必要工作超过预算提供可解释的分段或范围选择；确需增加额度时按任务授权策略处理，明确尚未完成的部分。不无声截断、不伪报成功，也不无限重试。
任务结束与后台结算回填全部实际账单及分摊，标记成功、失败、部分完成或费用未确认。预估值、预算上限和实际费用分别呈现。

上下文配置独立推进：后续扩大正常窗口时，基线和候选使用相同可用材料及相同容量条件重新对照。窗口容量变化不计为本方案的处理效果；必要的长上下文任务应单独分组观察。

06

同样的材料，交付同样完整的结果

基线与候选使用等价独立会话、相同真实模型路由、提示词基线、可用材料、上下文容量和交付要求；单独记录本次有意调整的策略版本。短问答、检索、长材料、多轮记忆分别报告，不以混合均值掩盖退化。

验收项方法通过要求
实际成本覆盖前台、后台、失败、重试与降级；等待维护和账单结算，比较完整任务均费及 P95，报告样本量和波动。个人助理完整试点首要目标为同口径均费下降 30%；40%–50% 为进一步目标，均需实测。这不是所有智能体的统一指标；单步收益只按其覆盖范围声明。
材料完整性长文、清单、跨段约束、早期关键原文、工具调用完整组；对扩大后的正常窗口单独复测。不丢关键材料与协议依赖；原文来源可回查，未覆盖明确标记；不靠缩小窗口达标。
事实与回答质量普通问答、证据不足补查、个人历史、更正、撤回、冲突和含糊表达逐项对照。关键事实、来源、纠正和撤回用例全部通过；任务完成率及正式业务门禁不降低。
后台收敛连续快问、维护延迟、积压合并和长会话，观察实际覆盖游标与完成时间。不遗漏新增内容；普通维护最长收敛候选 60 秒须在约定负载下验证，不以少处理事实换取低费用。
重复付费与恢复租约冲突、并发副本、重复投递、部分输出失败、状态不明的付费请求及进程中断。不重复推进、不重复记账；所有真实付费保留，重试受统一额度约束，失败部分可定位。
速度与可靠性比较首字和完整交付 P95、错误率、后台排队，保留全部失败与重跑。建议 P95 相对对照恶化不超过 10%；既有可靠性门槛保持，未达标不扩大灰度。
删除与权限隔离不同 owner / agent / env / session，相同内容及排队 / 执行中删除。授权边界不变；不串会话、不复活删除记忆；成本控制不能绕过权限、审计或来源校验。

以上是待执行标准，没有新增验收通过声明。不为本文档创建付费测试；实施阶段的真实模型评测和负载费用应单独计入测试预算。
