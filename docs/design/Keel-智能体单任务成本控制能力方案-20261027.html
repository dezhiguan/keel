平台原则

统一成本机制，业务策略分别验证。不新增“成本优化智能体”或为每轮请求额外调用模型；不引入缓存。临时 10,000 token 输入上限不作为平台优化目标，也不固化为所有智能体的默认窗口。

配套试点：个人智能助理成本优化试点方案负责真实账单、助理业务调整、试验参数和降本目标。本文负责公共机制及后续新智能体自动接入，不将助理参数推广为全平台默认值。两份文档共同替代原单份成本方案。

01

默认具备机制，按能力启用策略

默认接入任务归因、费用观测、基础预算与重试协调
按需启用记忆调度、检索证据和业务执行策略
分型验收质量、完整性、费用、可靠性分别验证

“新建智能体自动具备”指：平台发布相应能力、正式 SDK 和生成模板后，新项目通过标准入口自动携带可信任务关联、继承适用策略，并能查询真实费用和控制结果。不是承诺所有智能体采用相同窗口、步骤、维护频率或降本比例。

现状与新增设计必须区分
能力当前可确认基础本方案需要补齐
网关与费用已有实际模型结算、按尝试计费、日费用 / 历史恢复，以及部分调用用途配置。业务根任务归因、跨子任务与后台分摊、统一任务级预算执行和控制事件。
记忆维护Python SDK 已有维护任务执行、局部费用上界与选择性合并；底座有持久任务、租约及版本校验。与根任务预算打通，形成按能力启用、可版本化的策略和接入检查；不能将维护局部上界当完整任务费用。
业务路由个人助理已有规则识别、慢分类和本地执行路径。公共运行约束与业务步骤解耦；助理的规则和语义判断不直接固化进全平台。
新项目接入工程使用已发布且锁定的 SDK；各项目现有接入程度不同。同步生成模板、正式 SDK、登记校验与接入验收。Java 等路径须核验能力覆盖，不默认与 Python 等价。

本文是目标设计，不是自动接入已完成的声明。默认开启的内容处理策略必须有独立证据，不能仅因公共代码已存在就认定所有项目已启用。

02

一份权威费用账，覆盖完整任务链

业务根任务由受信入口建立；交互回复、后台分析、工具步骤、维护任务和允许的子任务可形成关联。根任务、执行记录、模型请求和付费尝试是不同统计对象，不能相互替代。

完整任务成本 ＝ 分类 ＋ 回答 / 分析 ＋ 工具后的模型处理 ＋ 归属该任务的记忆维护 ＋ 重试 / 降级尝试 ＋ 其他可归属直接服务费用模型费用以网关 SETTLED 且金额非空的实际尝试为准；预估、预留、预算上限与结算分别记录。
  • 跨前台、后台和允许的子任务传递可信根任务关联、用途与策略版本。任务归属、owner、agent、env 等由平台校验，不能采信用户正文中的自报值。
  • 同一付费尝试按 attemptId 去重；不同重试与降级尝试分别计费。父节点汇总与子节点费用不重复相加；模型 requestId 去重调用数与业务任务数分别呈现。
  • 共享维护只计一笔真实费用。按显式且版本化的分摊规则分给覆盖的任务，保留范围和依据；不同业务可选择适用规则，不强制使用助理的等额分摊。
  • 执行状态与费用状态分别管理。主回答完成不等于维护已完成或账单已结算；待结算、状态不明、未归属费用均单列，不默认为零。
  • 日常、评测、压测使用可信入口标记分组；失败成本保留。报告总支出、成功率、完整任务均费及 P95，并计算含失败支出的单位成功成本。

对账不变式：同范围已分摊费用＋独立后台费用＋未归属费用＝权威账单费用。历史 daily-recovery 只恢复有证据的日金额，不制造 task、模型、token 或小时明细；业务任务归因缺失时明确显示不可拆分。

03

机制下沉，语义判断留在业务

层级公共职责职责边界
底座可信任务生命周期、费用归因与分摊、策略解析 / 快照、权威任务预算、持久后台任务、租约与版本。不替所有业务判断材料是否充分，不通过删除输入来保证低价。
模型网关实际模型与路由定价、尝试结算、预算准入与预留协调、重试 / 降级尝试记录。不能只靠某个 SDK 进程的本地计数执行全局预算，也不能静默切换不符合任务质量要求的模型。
公共 SDK任务关联和调用用途传递、token / 费用预估辅助、完整协议组处理、上下文组装扩展点、公共维护执行及追踪。保证调用协议与来源信息；哪些资料相关、如何分段的业务判断由智能体提供。客户端预估不是结算或授权依据。
生成模板 / 登记锁定兼容 SDK、接入标准入口和生命周期、选择能力组合、绑定策略版本，校验覆盖情况。创建时接入不等于业务质量验证通过；不得将不具备的能力标为已启用。
智能体业务任务类型、材料范围、必要步骤、检索充分性、输出要求、工具副作用及恢复方式。只通过正式 SDK 使用公共能力，不复制权威账本、租约算法或另建可绕过的预算执行器。

公共能力优先沿用已有模块；确有新增职责时在实施 spec 中明确边界。此处不预定新增微服务，也不把个人助理改造成平台的全局成本调度器。

04

继承有边界，策略可追溯

策略按“平台基线 → 组织 / 环境约束 → 智能体配置 → 任务要求”解析。任务可在授权范围内细化策略；高层硬约束不能被低层放宽，冲突在执行前明确返回。业务参数通过平台受管理配置注入，不在应用中写无依据的默认兜底。

策略类别新建智能体目标行为变更规则
任务归因与真实账单标准入口默认接入，后台继承可信关联；缺失或不支持时明确标记。不因选择更保守的内容策略而关闭记账，不伪报已完整接入。
基础预算与重试协调继承已发布的有效平台策略，不固化统一低费用或统一步骤数。额度按业务类型与材料规模确定；动态调整须在授权约束内并记录版本。
记忆调度声明并实际使用会话记忆时接入；无记忆业务不产生维护开销。维护批次、收敛要求、合并条件按业务验证，不能自动照搬助理试验值。
检索与上下文处理获得统计、完整协议组支持与处理扩展点。删减内容、缩减检索或改变工作步骤先观察 / 对照，再按业务启用；不设全平台固定输入窗口。
业务能力组合可组合基础、记忆、知识检索、长材料分析、执行任务等适用策略。组合时保留各能力的必要条件；名称是设计分类，不是已经存在的配置接口。
  • 每个根任务固定有效策略版本并记录 SDK / 模型 / 提示词版本；后台任务沿用其业务策略快照，紧急权限撤销和平台强制约束仍需实时校验。
  • 平台更新策略不让已有任务静默换行为；变更按版本灰度、可回退。现有未知付费预留与真实账单不因回退而清零。
  • 涉及内容和质量的策略先提供观察模式，再显式启用；“自动接入机制”与“自动改变业务回答”分别验收。
05

控制实际任务费用，协调并发与重试

时点目标机制边界
创建任务由业务声明材料规模、必要工作与交付要求；平台按策略及适用路由价格估算，建立任务预算和维护额度。不为预算估算默认新增一次模型调用；没有足够依据时明确预估不确定。
调用前准入按本次输入、允许输出及可用路由上界估算，原子检查已结算费用与未决调用预留；与现有网关准入协调。前台、后台和并发子步骤共享约束，不能各自读取余额后同时超支；路由变化必须重新检查。不能把模型最大窗口一律当作实际输入。
追加调用 / 重试统一计算应用、SDK、网关的尝试额度，保留尝试原因；仅对可恢复失败重试，成功部分不无条件重跑。不能让各层分别加倍重试。副作用操作使用业务幂等和执行核对，不能当纯模型调用重放。
结算与不确定状态实际账单到达后幂等核销对应预留，晚结算修正任务费用；中断或未知尝试进入待核对状态。同一尝试不同时重复计入已结算和未决预留；不能因超时直接释放未知付费占用。
接近或超过预算向业务返回可解释的控制结果，优先暂停可选工作；必要工作调整范围或额度按任务授权处理。不静默删除必要材料、不伪报完成、不绕过权限审计；延期维护仍归属原任务并遵守收敛约定。

预算、模型上下文能力和业务质量要求分别配置。正常上下文容量未来调整时，平台策略不应依赖临时测试上限；对照实验保持容量与可用材料一致，单独衡量处理策略的效果。

新增任务预算、关联或控制结果若涉及跨语言通信，先定义兼容的可选契约并登记错误码，再同步服务端与各 SDK。本文描述职责和语义，不将尚未实现的字段或端点当作现有 API。

06

让“自动具备”成为创建流程的一部分

新建项目：创建、登记、运行、验收四步接通

  1. 生成：模板锁定已发布的兼容 SDK，生成标准任务入口、受管理配置与成本用途传递；按智能体声明的能力选择适用策略。
  2. 登记：校验 SDK / 运行时能力及有效策略；不支持的语言或自定义运行时显示具体缺口，不能标为完整覆盖。需执行控制但缺乏支持时阻止该模式启用。
  3. 运行：从受信入口建立任务关联，后台和子执行继承；模型调用经标准 SDK 与网关，记录有效策略和费用状态。
  4. 验收：自动验证单请求、重试、后台关联、并发预算、待结算及策略回退；业务内容优化仍需对应业务质量门禁。

已有项目：按版本升级，不静默改业务

建立现有接入清单，升级并锁定正式 SDK；先完成观察和费用对账，再灰度执行控制，最后验证并启用适用业务策略。旧版本继续标注已覆盖 / 未覆盖范围；不能把“网关已有总费用”误认为“完整任务归因已接通”。

适用边界：自动接入只对通过受支持标准入口、SDK / 运行时和网关的项目成立。自定义流程、第三方服务及尚未支持的语言需要适配证明；不能仅凭生成模板就声称覆盖任意后续调用。

07

公共机制先行，跨类型验证后进入模板

阶段一
平台基础

明确契约与权威执行位置

建立根任务、实际费用和共享维护归因；实现统一预算与重试协调，避免重复权威账。验证策略版本、并发准入、未知结算及回退。

出口：公共机制可对账，范围与不支持项有明确记录；不声明所有内容策略已完成。

阶段二
个人助理

首个项目接入并验证业务策略

按配套试点完成观察、费用基线、上下文去重、检索证据组织和记忆调度对照；优先保持模型路由和容量不变。

出口：助理自身的真实质量、费用、可靠性和回退证据；试点参数不自动升级为平台默认。

阶段三
跨类型复验

选择查询型与长材料型代表

分别验证低记忆需求的工具查询、需要完整材料的长分析，校准能力组合和预算预估；必要时补充执行型的副作用与幂等边界。

出口：每类适用 / 不适用清单、质量与费用结果；不要求各类获得相同降幅。

阶段四
默认接入

发布 SDK、策略与生成模板

能力稳定后更新正式版本、模板和登记校验；新建项目默认接入公共机制，按能力继承策略，既有项目按升级计划推进。

出口：从创建到真实运行的自动接入证据、版本回退方案及覆盖清单。

本轮仅拆分设计文档。具体代码改动前另写对应实现 spec，并核对跨语言契约与既有架构；如实现涉及控制台展示，再执行项目的原型和 UI 对齐要求。

08

平台验收能力，业务验收效果

验收范围关键场景通过标准
真实费用归因前台、后台、共享维护、子任务、失败、重试、晚结算及历史恢复。费用守恒且可追溯；不重复、不把缺失当零，不制造历史任务明细。
并发预算多副本、同时调用、路由降级、客户端中断和未知付费状态。执行位置权威、预留幂等且结算核销正确；不能通过并发或重试绕过任务额度。
策略继承平台 / 组织 / 环境 / 智能体 / 任务冲突，版本发布、回退及权限撤销。高层约束不可绕过；有效版本可追溯；已有任务行为不静默变化，撤销实时生效。
自动接入用新模板创建最小项目，执行标准请求、重试与后台任务；同时检查既有项目升级。无需复制成本基础代码即可获得已承诺能力；SDK / 语言覆盖与未接入路径如实报告。
能力按需启用无记忆业务、记忆业务、检索业务、长分析及允许的执行任务。不产生无用维护；必要材料、步骤和副作用校验保留，不强制同一窗口 / 输出长度。
业务质量与费用每类相同问题、可用材料、容量、交付要求和等价会话；全部后台结算后对照。业务门禁不降低，各类费用 / 完成率 / P95 分报；平台无统一“下降 30%”承诺，助理目标只在试点验收。
隔离与维护可靠性跨 owner / agent / env / session、删除、租约冲突、CAS 与部分成功恢复。不串账、不串数据、不复活删除记忆；有效部分不重复执行，失败仍可定位。

验收证据记录代码 / SDK / 模型 / 提示词 / 策略版本、任务范围、实际账单和全部失败。费用预估、测试模型或调用数量减少不能替代真实完整费用；本文未执行新的付费评测。

09

已有依据与实施前待办

  1. 个人智能助理成本优化试点方案：首个试点的账单、业务策略、试验参数、验收与费用情景。
  2. 日成本、总成本与历史账单对账：权威费用来源、历史恢复精度与缺失明细边界。
  3. 记忆合并维护 spec、实施验收报告：已有公共维护机制、实际试验及其未通过项。
  4. Python SDK 维护执行：局部预算上界、任务执行与选择性合并的现有实现，不代表完整任务成本治理已完成。
  5. 网关调用用途配置实现：已有用途区分基础；动态任务预算、策略继承和自动接入仍需单独设计与落地。

实施前待办：盘点各语言 / 运行时与模板覆盖；确定根任务生命周期和可信传播；确定费用归因、共享分摊与预算权威模型；定义策略兼容及发布方式；逐项编写实现 spec 和验收矩阵。不新增缓存，不以临时窗口或某一业务试点参数作为平台默认。

本设计不嵌入凭据、用户原文或服务密钥。既有能力与待实施能力分别陈述；未把其他专项的成功当作本方案已经完成。
