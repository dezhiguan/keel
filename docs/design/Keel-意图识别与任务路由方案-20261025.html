01

范围与当前状态

先说明当前能做什么，再定义目标；远端能力必须有独立交付门槛。

审核结论。总体方向可行，v0.1 的契约与执行语义尚不足以直接开发。本版已修订正文，并保留第 09 节问题对照。当前仅授权更新设计；不代表契约发布、SDK 升级、远端功能启用或线上验收通过。

核查基准为 2026-10-25 本地 keel 与同级独立项目 keel-assistant 工作区（含当时未提交改动），未查询集群或线上版本。技术文档提供架构约束；“当前可运行”须由源码、测试与部署证据共同确认，不能把技术文档中的目标当成现状。

02

分层与授权边界

分类决定候选路径，执行层决定能否产生实际动作。

L0 确定性入口GATE
验证后的请求回执、明确且独立的任务命令、受控自检、空输入等由代码处理。命中后跳过分类模型，但继续走授权、工具/任务状态与审计检查。只有完整匹配受控命令才直办，材料内的“取消/发布”等文字不构成指令。
L1 意图识别INTENT
按当前消息及经授权的必要会话上下文，生成 IntentPacket。只说明目标、动作、参数与不确定性，不签发权限，不调业务工具。
L2 路由规划ROUTE
读取可信策略、权限和可执行能力快照，校验并形成 RoutePlan。复杂任务可在取得真实结果后有界重规划；每次新增动作重新校验。
已认证请求 + 当前消息 + 已授权会话上下文
        │
        ├─ L0 完整命中 → 代码构造最小 IntentPacket / RoutePlan
        │
        └─ 未命中 → L1 规则识别 / 必要时模型分类 → L2 校验规划
                                │
                                ▼
                       统一执行入口（逐步鉴权）
                                │
          ┌──────────┬──────────┼──────────┬──────────┐
          ▼          ▼          ▼          ▼          ▼
     local_fast  local_slow    remote      queue   clarify / deny / approval
          │          │       B 后开放     持久化回执       不执行待决动作
          └──────────┴──────────┴──────────┴──────────┘
                                │
                       真实结果 / 状态 / 证据 → 答复
                                │
                       路由与执行记录（L0 也覆盖）

不可被路由跳过的执行约束

每个动作的有效权限取已认证用户权限 ∩ 调用方 manifest 声明 ∩ 当前环境与目标版本策略 ∩ 具体工具/任务授权，并满足风险与审批要求。远端接收方独立验证身份与业务权限；不能只相信主控传来的 agent_id、side_effect 或预算。读取到员工信息不授予调用权限，清单中的 delegates 也不代替当前用户许可。

风险来自可信工具/能力定义及运行时策略；模型提示只能提高人工复核需求，不能降低风险。高风险动作在产生业务副作用前同步写审计，写失败则拒绝；审批同意后执行仍需检查授权、参数和版本。L0、重试、恢复、Worker 与重规划均走同一约束。

规则优先级。先识别当前用户指令与材料边界；再检查精确命令/已有回执；按步骤做权限与风险校验、必填参数及条件检查、路由选择。缺权限是拒绝，缺对象/目标是澄清；需要已有合法审批流程时才进入 approval。“发布条件是什么”不能因包含“发布”而被当成发布命令拒绝。
03

意图与可信上下文

让结构能表达动作和参数，同时把权限事实留在可信运行时。

结构状态。以下是候选字段与语义，不是现行 keel/v1 已实现接口。独立 schema 的必填关系、大小上限、错误码与共享测试应在实施 spec 中登记；接入既有 invoke 时使用可选扩展，不改变现有必填字段。
IntentPacket（候选）
├── schema_version                 # 本候选结构版本；不冒充现有 invoke 版本
├── intent_primary                 # 下表枚举
├── intent_secondary[]             # 次意图标签；不代替可执行 steps
├── operation                      # task_manage 必须细分；其他意图按能力定义
├── complexity                     # trivial | simple | complex，仅作提示
├── needs_evidence                 # 是否要求真实来源
├── side_effect_hint               # none | read | write，不能作为授权依据
├── clarity                        # clear | need_clarify
├── slots                          # 按 intent + operation 使用封闭的类型化 schema
│   ├── env / agent_id / task_id    # 必须校验来源、格式、环境及归属
│   └── material_ref               # 仅引用已授权消息材料，不存原文到路由日志
├── missing_slots[]                # 缺少的字段；禁止补造身份和权限
├── confidence                     # 可空；未校准时不得当作正确率
└── reason_brief                   # 简短解释，默认不写审计、不含用户原文

RoutingContext（可信运行时单独注入，不由模型输出）
├── principal_ref / org_ref / session_id
├── input_digest / request_id / authorization_ref
├── caller_agent / env / policy_version / capability_revision
├── budget_limit / deadline_at / grant_expiry
└── traceparent / parent_task_id / parent_run_id

模型仅收到完成识别所需的最少上下文；JWT、Cookie、密钥及可执行授权票据不进入提示词或意图包。RoutingContext 中的引用不授予调用能力，执行层仍验证实际票据与当前授权。参数来源区分本轮指令、获准继承的会话槽位与材料数据；只有前两类可用于确定动作，材料只能作为数据处理。

主意图operation / 参数说明
chatreply；无业务工具闲聊、自我介绍、能力说明；复杂解释也可能保持本地无工具回答。
retrieve_knowledgesearch；query / 已授权知识范围规范、文档检索；需要真实检索证据或明确不足。
retrieve_statelist / detail；env / agent_id读平台登记状态；与健康探测分开。
retrieve_historysearch；query / exact / role本人授权范围内的历史原文；用户问句和历史模型回复不自动构成事实。
task_manageprepare / create / supply / get / list / cancel / retry每个动作使用独立参数 schema；写入需当前任务授权；重试额外要求费用确认。
analyze_documentsubmit；material_ref / task_type表达新分析目标。当前助理由执行层映射到 task_manage.create 或 prepare；后续管理该任务用 task_manage。
delegate_workdelegate；capability_id / goal_ref用户目标需要已授权其他执行者；对象不明则澄清，运行时未启用则拒绝。
action_request具体策略声明的动作，例如 release发布等是动作类别，不天然等于越权；当前助理策略拒绝这类管理动作。
mixed各步骤独立定义多目标、条件或依赖请求；次意图标签不能代替步骤图。
unknown无可执行动作识别不足；进入澄清或仅提供受限解释，不能默认当成聊天后任意调用工具。

参数与槽位约束

task_id 必须符合现有格式并由任务服务确认归属；env 不能默认补 staging，agent_id 不能从模型臆造；明确用户纠正覆盖旧槽位。查询可从可信会话上下文继承唯一对象；创建、取消、重试等写动作仍必须由本轮授权和原文检查确认。多个候选不能按最近一条记录擅自选择。

对于 analyze_document，当前助理“目标明确且有直接文字材料”创建入队任务；目标明确但材料缺失/只有链接时沿用 prepare → waiting_input；没有目标或仅讨论能力时先澄清、不创建。材料限制沿用现行不超过 12000 字符，不新增文件下载或未授权检索。

快慢识别与降级

保护已有聊天延迟；分类失败也必须有可预测的行为。

当前指令 + 必要且已授权的会话槽位
       │
       ├─ L0 明确独立命令 / 已验证回执 → 无分类调用 → 统一执行与记录
       │
       └─ 未命中 → L1 规则
                    │
                    ├─ 已验证规则完整命中、无歧义/混合/条件 → IntentPacket
                    │
                    └─ 歧义、复合或需消歧 → 可选慢分类
                                              │
                           关闭用户 token 输出 + 本地 schema/语义验证
                                              │
                           有效 → L2      无效/超时 → 明确降级策略
事项修订要求
快路径规则返回 rule_id、匹配范围与候选结构；否定、引用材料、第二动作、条件或对象冲突时不做宽松直办。保留现有明确命令解析，不让新分类器强制包住所有请求。
置信度删除未校准的固定 0.85 门槛。规则命中由语法与回归证明，模型 confidence 仅作辅助；未来阈值须以独立评测集校准并记录版本。
何时用慢分类仅在能改善路径/槽位选择时增加一次受预算约束的分类。复杂问题不必都分类，明确写入也不因副作用大而必须先调模型；安全性由执行校验保障。
SDK 前置所有模型调用仍走 ctx.llm。先为受支持网关/模型补结构化输出能力声明、适配及测试，再启用慢分类；不能直连厂商 SDK，也不能把提示词 JSON 当作强制 schema。
输出控制分类调用必须 emit_tokens=False；不向用户发分类 JSON，不把其记入会话事实。temperature 等参数通过当前受支持的提示词配置设置，temperature=0 不保证结果合法或确定。
本地验证验证 JSON 对象、枚举、字段类型、长度、数值有限性、必填槽位关系、材料引用及能力标识；不执行模型返回的工具调用、URL 或 executor。额外字段与不支持结构按明确策略拒绝。
失败处理分类失败不重复调用直到成功。写入/委派或目标不明时 clarify；明确越权由策略 deny；已有可信只读意图时可退回当前受限只读 loop，并记录降级原因。现有可执行计划不因分类失败扩权。
成本与延迟记录 classify 调用数、耗时、tokens 与真实费用，计入父任务预算和 deadline。已提交业务动作之后不得重新分类并再次提交同一动作。
开启门槛。SDK 适配与分类专项验收完成前，Phase A 仅统一现有规则/模型协调路径的路由表达，保留已有受限 loop；慢分类保持关闭。不能因本设计写了“强制 schema”就认为当前客户端已支持。
05

路由与步骤依赖

统一模式，补齐任务动作；独立性和用户条件决定能否部分执行。

RoutePlan（候选；根计划和每个子步骤使用同一 mode 枚举）
├── plan_id / request_id / schema_version
├── mode                 # local_fast | local_slow | remote | queue | clarify | deny | approval
├── executor             # self 或经校验的 {agent_id, env, version, capability_id}
├── policy_version / capability_revision / reason_code
├── budget_cap_cny / deadline_at / max_attempts
├── retry_policy         # 不代替当前任务的费用确认与状态机
├── parent_task_id / parent_run_id / traceparent
├── partial_policy       # independent_only | require_all
└── steps[]
    ├── step_id / intent / operation / mode / executor
    ├── input_refs / output_contract
    ├── depends_on[] / precondition
    ├── required_grants / approval_ref / evidence_requirements
    └── budget_cap_cny / timeout_seconds / max_attempts / on_failure

Mode 表达当前计划的执行路径：local_fast 是代码直办或少量直答；local_slow 是工具循环/主控编排；queue 表示持久化受理并返回回执，executor 单独说明谁执行；remote 表示实际远端调用步骤；clarify / deny / approval 不执行业务动作。当前 queue 仅由 self 执行；未来排队后委派须以 queue 父任务和 remote 子步骤表达，并单独交付运行时。

不再使用 remote_agent、queue_job、human_gate 作为别名。根计划含多个步骤时使用 local_slow；每步单独记录 mode，执行状态另行记录，不能用“全部拒绝”的根模式承载已执行的子动作。无动作的 clarify/deny/approval，executor 为空。

路由规则及优先级

条件 / 意图模式执行约束
原请求已存在有效回执local_fast先完整校验回执授权，再读持久化状态；不重新提交或重新调用分类模型。
明确独立任务查询/取消等命令local_fast沿用固定语法与真实工具；缺必填参数 clarify；有权限也要遵守任务状态机。

动作未授权或当前不支持deny由可信策略判定，不取决于模型风险标签；不能由复杂度规则覆盖。
缺目标/参数/条件不明clarify只询问真正缺失信息；不反复追问已有可信唯一槽位。
合法但需人工审批approval只在已有审批运行时和明确策略支持时进入；当前助理不通过此模式绕过不支持的发布动作。

请求关系执行方式示例
独立且用户未要求整体完成independent_only：允许执行独立的获准步骤，明确未执行项及原因。查员工列表，并请求不受支持的委派：可查列表，拒绝委派。
结果依赖depends_on 表达前置步骤；等待真实成功结果，不能用“都是只读”决定并行。askdb 查故障率 → 运维根据该结果建议：两个 remote 步骤串行。
条件请求precondition 只引用可信策略或已校验结果，未知条件先澄清/暂停；前置拒绝则依赖步骤不执行。只有允许发布才创建工单，否则什么都别做：发布不允许时，零工单写入。
要求整体完成require_all：执行前做完整可行性检查；有一项已知不可执行则不开始。不承诺跨系统原子事务；中途失败可能已有副作用，必须记录并按明确补偿策略处理。
并行仅无依赖且允许并发的只读步骤；还受并发上限、共享预算与截止时间限制。多个独立知识来源查询；当前助理不因该原则自动获得远端并行能力。

计划必须校验步骤 ID 唯一、依赖存在、无环、输入输出兼容和步骤数量上限。重规划递增计划修订号，保留旧计划及已提交动作；原 request_id/step_id 稳定，不能通过重规划换 ID 绕过去重。

06

执行与故障恢复

保留现有任务可靠性；远端不能只靠换票和 HTTP 成功。

当前任务链路的保留约束

已认证当前请求 → 明确命令 / 受限协调 → 任务服务校验
      │
      ├─ prepare → waiting_input → 本轮用户供材料 supply → queued
      ├─ create  → queued → Worker 领租约 → 权限复验 → running
      │                                            │
      │                       验收中 validating → succeeded / failed
      │                                            │
      │                       断流/租约失联且结果不明 → unknown
      └─ 写入成功 → 回查持久化 receipt → 聊天返回真实 task_id / state

cancel：queued 等可执行前取消；运行中只请求停止后续步骤
retry：仅允许状态 + 用户明确请求与重复费用确认 + 当前授权；次数上限沿用现有规则

保留 assistant_analysis_task / attempt / command 的请求去重、材料摘要、授权引用、revision、租约及 fence；旧 Worker 不能覆盖新尝试。等待授权用 waiting_authorization，执行时授权失效不得沿用旧票据。命令回执读取失败不能虚构成功；已经确认写入后，后续模型错误不能被呈现为“没有任务”，应通过现有受控回执读取真实状态。

同一轮最多一次任务写入；L0、模型路径与重放共享约束。HTTP/SSE 断开不等于任务取消；cancel_requested 不等于模型已经停止，已发生计算与费用不能撤回。unknown 不自动重算，当前任务最多两次执行及明确重复费用确认规则优先于通用 retry_policy。

Phase B 的远端运行时前置条件

前置条件必须交付的语义
可执行能力目录按 agent_id + env + 已批准 version 定位能力、输入输出 schema、授权要求、支持的 task 类型、查询/取消/去重能力；区分登记状态与可执行可达性。现有员工只读列表不充当此目录。
身份与数据隔离解析端点时绑定目标环境/版本，服务端独立鉴权；只转交该步骤所需且当前用户允许共享的数据，禁止把全部历史、凭据或不相干材料透传给子员工。
持久化受理与幂等按认证主体、调用方、目标 agent/env/version、稳定 request_id + step_id 建立去重和输入摘要约束；相同键不同输入拒绝，相同请求返回同一持久化任务/回执。去重记录与受理事务保证一致。
未知结果与查询接收后断流/超时：优先按稳定 ID 查询原执行；无权或无法确认时保留 unknown，不当作“没执行”再次提交。外部非幂等副作用仍需业务去重/对账，不能宣称端到端 exactly-once。
取消声明是否支持、在哪些阶段可取消、取消请求的幂等行为及最终状态；不支持则返回能力不足。该受控委派路径要求可核对取消语义，不能用关闭 HTTP 连接充当取消成功。
有界恢复统一总 deadline、单步超时、尝试次数、并发数、最大委派深度及循环检测；断流/超时的自动重提须先由远端幂等与查询保证安全。缺少这些能力不开放分布式重试。
契约与共享测试先登记 contracts 的可选扩展、状态、错误码与测试；再实现 Python 与 Java。外部 auth-gateway 等接口以当前已验证规则为准，未核实项保留 TODO 并阻断相关能力启用。

预算、费用与追踪

预算单位使用明确 CNY 金额与截止时间，由可信配置注入；并行前原子预留子步骤额度及主控汇总额度，分配总额不得超过父预算。重试、分类、汇总都计入总限额。预算执行需网关/账本支持，不能只靠传递数字；预留机制未交付前不开并行远端硬预算保证。

实际费用以网关账单 request ID 与用量为准；SDK delegate 的固定 0.1 扣减不是真实费用。未调用模型标记“未调用”，账单尚未确认标记“待对账/未知”，不能写成 0 元。父任务总费用聚合去重后的自身及子步骤实际账单，避免同时累加父汇总值和子明细。

同步调用传播 W3C traceparent，通常共享 trace_id，由不同 span_id、run_id、task_id 区分执行。异步 Worker 可新建执行 trace，持久化 parent_task_id / parent_run_id / 原 trace 上下文并以 span link 或显式关联串联；不能为满足“子 trace”验收而强制每个子调用换 trace_id。参照 W3C Trace Context。

审计与路由记录

L0 命中也由代码生成最小意图/路由记录，记录 gate_rule_id 与 source=gate；纯协议自检和无有效业务输入的拒绝记录入口结果，不伪造用户意图。L1 记录 source=rule/model；每次执行记录 plan_id、step_id、policy_version、模式、执行者引用、结果及关联标识。reason_code 使用受控值，不直接存模型理由、材料、用户原文或票据。

路由元数据进入语义追踪/受控执行记录；需要写审计 payload 的字段必须先显式加入 manifest audit.captureFields 白名单并验证实际留存，例如 route_mode、intent_primary、operation、executor、plan_id、step_id。没有配置时会被过滤，不能声称全程可审计。沿用现有 action，新增 action 必须先改契约。拒绝/审批记录在决策时写，高风险获准动作在副作用之前同步成功写入；结果与真实费用随后补充独立事件，不 UPDATE 既有审计事件。

非高风险动作沿用有界上报与审计落盘重放要求；当前 MQ/存储的真实持久化配置需单独验证，不把设计要求当成已部署保证。普通 span 属性不存用户原文；模型输入输出按项目约定仅放 generation observation。

IR-01～10 保留原始主要场景并修正阶段与等价路径；IR-11～35 补覆盖纠正、否定、缺材料、写入回执、条件、授权与分布式故障。正式评测按阶段选取全部适用项，并扩展语言变体、对抗样例和并发组合；公开冒烟用例与独立评测集分开，避免只针对固定十句话优化。
